# 컴포넌트 — Components

각 컴포넌트는 **언제 쓰나 · 규칙 · 코드** 순서로 적는다.
코드의 `ui-*` 클래스는 `components.css`에 있고 (값은 `tokens.css`의 토큰), 모양은 견본 페이지 `specimen.html`에서 볼 수 있다.
문서에 있는 컴포넌트는 견본에도 있어야 하고, 견본에 없는 UI는 만들지 않는다.

**우선순위 규칙**: 컴포넌트 선택자는 `:where([data-ui]) .ui-x`라서 우선순위가 클래스 하나와 같고, `tokens.css`와 `components.css`가 다른 CSS보다 먼저 불린다.
그래서 페이지 CSS의 `.내-행 { display: grid; … }` 한 줄로 컴포넌트의 배치를 바꿀 수 있다. `!important`나 선택자 늘리기를 쓰지 않는다.

> 크기는 데스크톱(macOS) 기준으로 적었다. 폰에서는 [foundations.md §8](foundations.md#8-컨트롤-크기와-누르기-영역)에 따라 44로 커진다.

## 1. 버튼

**언제**: 동작을 실행할 때. 다른 화면으로 *이동*만 하면 링크(§2)를 쓴다.

**역할과 모양**

| 역할 | 클래스 | 모양 | 쓰는 곳 |
|---|---|---|---|
| 기본 | `.ui-btn` | 회색 채움(fill-3) + 검정 글자 (macOS 푸시 버튼) | 대부분의 동작, 취소 |
| 주요 | `.ui-btn.prominent` | 강조색 채움 + 흰 글자 | 화면의 **가장 중요한 동작 하나** (게시, 저장, 참가) |
| 파괴 | `.ui-btn.destructive` | 회색 채움 + 빨간 글자 | 삭제. **주요(prominent)로 만들지 않는다** |
| 테두리 없음 | `.ui-btn.plain` | 바탕 없음 | 카드 꼬리의 반응 버튼, "더 불러오기", 툴바 안 |
| 글자 | `.ui-btn.text` | 링크 색 글자, 여백 없음, 문장 안에 들어감 | "펼치기", "모두 읽음", 문장 끝의 "편집" |
| 켜짐 | `[aria-pressed="true"]` | 강조색 글자 + 강조색 12% 바탕 | 좋아요·투표처럼 켜고 끄는 버튼 |
| 유리 | `.ui-btn.glass` | 유리 캡슐 | 상단 바·캔버스 위 컨트롤에만 |

**크기**: `.small` 22 · 보통 28 · `.large` 34. 아이콘만: `.icon` (정사각형).

**규칙**
- 한 화면에 주요 버튼은 1개, 많아야 2개. 우선순위는 **크기가 아니라 스타일**로 나타낸다 **[HIG]**.
- 짝을 이룰 때: **취소는 앞(왼쪽), 실행은 뒤(오른쪽)** **[HIG]**.
- 라벨은 동작어 ([writing.md §3](writing.md#3-동작어-표)). 눌렀을 때 입력이 더 필요한 창이 열리면 끝에 "…"를 붙인다 — "일정 수정…" **[HIG macOS]**.
- 아이콘은 글자 앞에 둔다. 아이콘만 있는 버튼은 `aria-label` + `title` 필수.
- 처리 중에는 버튼 안에 스피너 + 진행형 문구: `.is-loading` + "게시하는 중…". 처리 중엔 다시 누를 수 없다.
- 비활성(`disabled`)은 이유가 보일 때만 쓴다. 이유가 안 보이면 활성으로 두고 누르면 무엇이 빠졌는지 알려 준다.
- 버튼에 `margin`을 넣지 않는다. 간격은 부모(`.ui-row`, `gap`)가 정한다.
- 동작하는 칩(날짜 이동, + 태그 추가)은 칩이 아니라 `.ui-btn.small`이다. 투표는 `.ui-btn.small` + `aria-pressed`.

```html
<button class="ui-btn prominent"><i data-lucide="pen-line" class="ic"></i>새 게시물</button>
<button class="ui-btn">취소</button>
<button class="ui-btn destructive"><i data-lucide="trash-2" class="ic"></i>삭제</button>
<button class="ui-btn plain icon" aria-label="더 보기" title="더 보기"><i data-lucide="ellipsis" class="ic"></i></button>
```

## 2. 링크와 뒤로

- **문장 안 링크**: 그냥 `<a>` — `--link-text`(= 강조색), 호버에 밑줄.
- **목록·카드 전체가 링크**: 카드나 행을 `<a>`로 감싸고 호버에 바탕색만 바꾼다. 글자를 파랗게 칠하지 않는다.
- **글자 버튼처럼 보이는 동작**(접기·펼치기, "모두 보기"): `.ui-btn.text`.
- **뒤로**: 상세 페이지 왼쪽 위에 하나, `.ui-btn.text.back`. 이전 화면으로 돌아가면 "← 뒤로" — `AppUI.back(대신 갈 주소)`: 방문 기록이 없으면 대신 갈 주소로, 정해진 상위 화면으로 가면 그 이름("← 프로젝트").

## 3. 세그먼트 컨트롤

**언제**: 같은 화면 안에서 보기를 바꿀 때 (피드 탭, 상세 페이지 탭, 목록 종류 전환, 관리 탭, 차트 기준 전환).

**규칙** **[HIG]**
- 5개 이하. 각 칸은 같은 너비. 라벨은 짧은 명사 (아이콘만 쓰면 모두 아이콘만).
- 개수를 보여줄 때는 라벨 뒤에 회색 숫자 — "질문 3".
- 선택은 `aria-pressed="true"` (버튼) 또는 `aria-current="page"` (링크).
- 다른 페이지로 *이동*하는 탭도 같은 모양을 쓴다 (주소가 바뀌는 탭은 `<a>`).

```html
<div class="ui-seg"><button aria-pressed="true">개요</button><button>활동</button><button>설정</button></div>
```

작은 세그먼트는 `.ui-seg.small`.

## 4. 입력

**종류**: 글 입력(`input`), 여러 줄(`textarea`), 선택(`select` = macOS의 팝업 버튼), 날짜·시간, 검색(§22), 태그 입력, 파일 놓기.

**규칙**
- 라벨은 입력창 **위**에 (`.ui-label`, Callout · label-2) **[결정]**. 플레이스홀더로 라벨을 대신하지 않는다.
- 플레이스홀더는 예시나 범위 — "예: 회의실, Zoom", "문서·사람·프로젝트 검색".
- 도움말은 입력창 아래 Callout · `--label-meta`. 오류는 같은 자리에 `--danger` + 무엇을 고칠지.
- 높이: 데스크톱 28 · 폰 44. 글자: `--t-body`.
- 바탕 `--fill-4`, 테두리 없음, 포커스에 강조색 링.
- **모든 기본 입력창(`input`·`textarea`·`select`)이 자동으로 이 모양이다** (`components.css`의 우선순위 0 규칙). 클래스를 붙이지 않아도 되고, 문맥에서는 폭과 간격만 정한다.
- 태그 입력·파일 놓는 곳·별점 입력도 입력창과 같은 바탕·둥글기를 쓴다 (태그 입력은 `.ui-chip` + 입력창).

```html
<label class="ui-label" for="ev-place">장소</label>
<input class="ui-field" id="ev-place" placeholder="예: 회의실, Zoom">
```

## 5. 체크박스·스위치·할 일 체크

| 컴포넌트 | 클래스 | 언제 |
|---|---|---|
| 체크박스 | `.ui-check` | 데스크톱의 켜고 끄는 옵션, 여러 개 고르기 **[HIG macOS]** |
| 스위치 | `.ui-switch` | 목록 행 안에서 기능 하나를 켜고 끌 때 (폰 설정 화면 같은 곳) |
| 할 일 체크 | `.ui-done` — 원형, 누르면 강조색 채움 + 체크 | 준비 목록, 읽음 표시 (미리 알림 앱처럼) |
| 라디오 | 쓰지 않는다 → 2–5개면 세그먼트, 그 이상이면 선택(select) |

- 상태를 색만으로 보여주지 않는다 (체크 표시가 있어야 한다).

## 6. 태그·칩·필·배지

모두 둥근 알약 모양이라 섞이기 쉽다. **역할로 구분한다.**

| 컴포넌트 | 클래스 | 역할 | 모양 |
|---|---|---|---|
| 태그 | `.ui-tag` | 항목의 분류(주제·종류) 표시. 누르면 그 분류 페이지로 | 색 점 + 이름, Subheadline. 첫째 분류 축 = fill-3 채움, 둘째 분류 축(`.ui-tag.method`, 예: 방법·형식) = 테두리(inset 1px separator) |
| 필터 칩 | `.ui-chip` | 켜고 끄는 필터 | fill-3, 켜지면 강조색 18% 바탕 + 강조색 글자, `aria-pressed` |
| 상태 필 | `.ui-pill` + `.warn` `.ok` `.accent` | 상태 하나를 짧게 — "7일 늦게", "완료", "진행 중" | 색 16% 바탕 + 같은 색 글자, Subheadline |
| 숫자 배지 | `.ui-badge` | **안 읽은 알림 개수에만** | 빨간 타원 + 흰 숫자 |

- 개수(질문 3, 댓글 12개)는 배지가 아니라 회색 글자로 쓴다.
- 칩·태그 안 글자는 한 줄. 넘치면 줄임표.
- 칩은 켜고 끄는 필터만이다. 동작하는 칩은 버튼(§1)으로 만든다.
- 아바타 + 이름 칩은 `.ui-chip` 안에 `.ui-avatar.xs`.

## 7. 아바타

| 크기 | 클래스 | 이니셜 | 쓰는 곳 |
|---|---|---|---|
| 20 | `.ui-avatar.xs` | 10 (Caption 1) | 문장·칩 안, 댓글 |
| 28 | `.ui-avatar.s` | 11 | 목록 행, 아바타 묶음 |
| 36 | `.ui-avatar` | 13 | 콘텐츠 카드 머리, 사람 카드 |
| 56 | `.ui-avatar.l` | 20 | 프로필 페이지 머리 |

- 이 네 크기만 쓴다: 토큰 `--av-xs/s/m/l`, 이니셜 `--fs-av-xs/s/m/l`. 이니셜은 폰에서도 커지지 않는다 (원이 커지지 않으므로).
- 바탕 = 사용자 색, 이니셜 색은 자동(흰/검정) — [foundations.md §2-5](foundations.md#2-5-사용자가-고르는-색--예외-결정). 시스템·관리자 계정은 `.ui-avatar.system`(강조색 바탕). 사진이 있으면 안에 `<img>`.
- **아바타 묶음**: 겹침 −4px, 바탕색 2px 고리, 넘치면 "+N" 칩 — `.ui-avatar-stack` 안에 아바타들, 끝에 `.ui-avatar-more`. 묶음에는 최대 5명.

## 9. 카드

**언제**: 하나의 대상(문서·사람·프로젝트)이나 하나의 묶음(사이드 정보)을 감쌀 때.

**규칙**
- 바탕 `--bg-grouped-2`, 둥글기 `--r-card`(20), 안쪽 여백 `--s-4`, 카드 사이 `--s-6`(24). **테두리 없음.**
- **카드 안에 회색 상자를 넣지 않는다.** 메모·안쪽 항목·질문은 위쪽 0.5px 구분선으로 나눈다 (설정 앱의 행처럼). 서랍·모달 안의 카드만 `--fill-4`.
- 카드 제목은 `h3` + Title 3 (15), 카드 안 섹션 머리는 Subheadline · label-2.
- 카드 전체가 링크면 호버에 바탕을 살짝 바꾼다 (`color-mix(... 94%, label 6%)`). 들썩이는(transform) 효과는 쓰지 않는다.
- 종류를 왼쪽 색 줄로 나타내지 않는다 — 머리에 아이콘 + 필.

```html
<section class="ui-card"><h3 class="t-title3">최근 활동</h3> … </section>
```

## 10. 목록과 행

macOS 앱의 목록처럼 **한 줄 = 한 항목**, 구분선으로 나눈다. 행 모양은 세 가지만 쓴다.

| 행 | 클래스 | 높이 (데스크톱) | 내용 | 예 |
|---|---|---|---|---|
| 한 줄 | `.ui-row` | 28 | 아이콘·아바타 + 글(Body) + 오른쪽 값/꺾쇠 | 사이드 카드 목록, 분류 목록, 차트 범례 |
| 두 줄 | `.ui-row.two` | ~40 | 제목 + 메타(`.m` · Callout · label-meta) | 알림, 나중에 볼 목록, 사이드의 일정 |
| 풍부한 행 | `.ui-row.rich` | 내용만큼 | 제목 + 메타 + 태그·아바타 묶음 | 큐레이션 목록의 항목 |
| 구분선 행 | `+ .ruled` | — | 위쪽 0.5px 구분선, 좌우 여백 0 (글자 시작선이 카드 제목과 같음) | 카드 안 후보 목록, 나중에 볼 목록 |

- 행은 기본이 flex다. 칸이 여러 개면 페이지 CSS의 배치 고리(`.내-행 { display: grid; grid-template-columns: … }`)가 배치만 정한다.
- 링크·버튼·`data-open` 행은 마우스를 올리면 바탕이 바뀐다.

- 묶음: `.ui-list` (카드 모양), 머리말 `.ui-list-h`, 꼬리말 `.ui-list-f`.
- 구분선은 글자 시작 위치부터 (아이콘이 있으면 아이콘 뒤부터).
- 들어가는 행(드릴다운)은 오른쪽에 꺾쇠 `›` (`chevron-right`, label-3).
- 선택된 행: 강조색 바탕 + 흰 글자 (전역 검색·메뉴의 키보드 선택처럼).
- 마우스를 올렸을 때만 보이는 동작은 키보드 포커스 때도 보여야 한다.

## 11. 표

**언제**: 관리자 화면처럼 같은 속성을 가진 항목을 열로 비교할 때. 그 외에는 목록을 쓴다.

- `.ui-table`.
- 머리: Subheadline · label-2 · 600, 아래 구분선. 정렬 가능하면 머리를 누르고 화살표 표시.
- 행: 높이 28, 구분선. 숫자 열은 오른쪽 정렬 + `tabular-nums`.
- 표 안의 입력·버튼은 `.small`.

## 12. 콘텐츠 카드

사용자가 쓴 콘텐츠 하나(예: 게시물·리뷰)를 보여 주는 카드. 서비스의 중심 콘텐츠라면 **렌더 함수 하나에서만** 만든다. 바탕은 `.ui-card`.

```
┌───────────────────────────────────────────────┐
│ (아바타 36) 작성자 · Headline          [⋯]   │  머리
│            ★★★★☆ · 10월 2일 · [7일 늦게]       │  메타: Callout · label-meta, 필
│ 제목 (Headline, 링크)                          │  제목 (그 대상의 페이지 안에서는 생략)
│ 본문 (Body) — 접혀 있으면 아래로 페이드         │  본문
│ 더 보기                                        │
│ ─────────────────────────────────────────────  │  구분선
│ MEMO (Caption 2, 강조색)                       │  메모 — 바탕 없이 구분선 아래
│ 덧붙인 생각·한계                               │
│ [PDF] [이미지]                                 │  첨부
│ (분류 태그) (둘째 분류 태그)                   │  태그
│ [좋아요 3] [댓글 2] [번역] [공유]              │  꼬리: .ui-btn.plain.small (아이콘 + 글자)
└───────────────────────────────────────────────┘
```

| 변형 | 언제 | 모양 |
|---|---|---|
| 기본 | 피드, 대상 페이지 | 카드 |
| `.full` | 콘텐츠 하나를 읽는 화면 | 본문 접지 않음 |
| `.mine` | 내가 쓴 것 | 머리에 "내 글" 필, 편집 버튼 (바탕색은 같음) |
| `.blind` | 아직 볼 수 없는 내용 (예: 내 것을 쓰기 전에는 남의 것을 가리는 설정) | 본문을 가리고 이유를 적음 |
| `.missing` | 아직 채워지지 않은 자리 (예: 아직 내지 않은 사람) | 점선 테두리, 바탕 없음 |
| 안쪽 | 서랍·모달·카드 안 | `--fill-4`, 그림자 없음 |

- 메모 칸은 강조색을 섞은 면으로 칠하지 않는다 — 구분선 아래에 바탕 없이 둔다.
- 사용자 색은 아바타에만. 카드 테두리나 줄로 쓰지 않는다.
- 본문 글자 크기는 변형마다 다르게 하지 않는다.

### 12-1. 묶어 접는 목록 (예: 한 사람의 게시물 목록)

한 사람·한 대상의 콘텐츠를 훑고 찾는 목록. 같은 내용을 보여 주는 화면(프로필, 내 페이지)은 같은 컴포넌트를 쓴다.

```
[제목·내용 검색 …] [기간 ▾] [분류 ▾] [둘째 분류 ▾] [댓글 있는 것만]      ← 도구줄
12개 중 4개 · (분류 이름 ✕) 필터 지우기                                ← 걸린 필터: .ui-chip[aria-pressed]
▾ 2026년 9월  5                                                      ← 달 묶음 (최신 달만 펼침)
  제목 (분류 태그)                               2   09-23   [편집] [삭제]  ← .ui-row, 편집·삭제는 내 것을 관리하는 화면만
    └ 누르면 그 자리에 콘텐츠 카드(.full, 안쪽)가 펼쳐짐
```
- 행을 누르면 접고 펼친다 (키보드 Enter·Space). 행 안의 태그·버튼은 펼치지 않는다.
- 남이 보는 프로필은 읽기 전용. 내 것을 관리하는 화면에는 편집(링크)·삭제(`AppUI.confirm`)가 붙는다.
- 필터·차트 칸을 고르면 결과가 있는 달을 모두 펼친다.

## 13. 메뉴

**언제**: 버튼(⋯, 내 메뉴, 관리)을 눌러 동작 목록을 펼칠 때.

**규칙** **[HIG]**
- 항목은 동작어. 창이 열리는 항목은 "…" — "일정·장소 수정…".
- 관련 항목끼리 구분선으로 묶는다. **파괴적 항목은 맨 아래, 빨간색.**
- 하위 메뉴는 1단계까지.
- 키보드: ↑↓ 이동, Enter 실행, Esc 닫기. 항목 높이 24–28, 둥글기 8 (메뉴 14 − 여백 6).
- 지금 상태를 보여주는 항목(테마·언어)은 메뉴 안에 세그먼트로.

```html
<div class="ui-menu ui-glass strong" role="menu">
  <button role="menuitem"><i data-lucide="calendar" class="ic"></i>일정·장소 수정…</button>
  <hr><button role="menuitem" class="destructive"><i data-lucide="trash-2" class="ic"></i>삭제</button>
</div>
```

## 14. 팝오버와 툴팁

**팝오버** (`.ui-popover`): 버튼에 붙어서 뜨는 작은 창 — 필터 설정, 기간 선택, 태그·멘션 자동완성, 알림 목록.
- 한 번에 하나만. 팝오버 안에서 또 팝오버를 열지 않는다. 경고에 쓰지 않는다 **[HIG]**.
- 바깥을 누르거나 Esc로 닫는다. 진한 유리, 둥글기 14.
- 폰에서는 시트로 바꾼다.

**툴팁**: 두 가지만.
- 아이콘 버튼 설명 → 브라우저 `title` 속성.
- 차트 값 설명 → `.ui-tooltip` 하나. 차트마다 따로 만들지 않는다. [data-viz.md §5](data-viz.md#5-공통-규칙).

## 15. 알림 (확인창)

**언제**: 되돌릴 수 없는 동작 직전, 또는 다른 사람에게 영향을 주는 동작 직전. 되돌릴 수 있으면 알림 대신 바로 실행하고 토스트에 "실행 취소"를 둔다 ([patterns.md §5](patterns.md#5-확인과-되돌리기)).

**규칙** **[HIG]**
- 제목 = 질문 ("이 게시물을 삭제할까요?"). 결과 설명은 **제목이 아니라 본문(message)**에.
- 버튼 최대 3개. **취소 왼쪽, 실행 오른쪽.** 실행 버튼 이름은 구체 동작어 ("삭제", "병합") — "확인"을 쓰지 않는다.
- 파괴적 실행은 `.destructive` (빨간 글자), 주요 버튼으로 칠하지 않는다.
- 구현: `AppUI.confirm(title, { message, ok, cancel, destructive })` → `Promise<boolean>`. 브라우저 `confirm()`·`prompt()`·`alert()`는 쓰지 않는다.

```js
const ok = await AppUI.confirm(t("post.delQ"), { message: t("post.delMsg"), ok: t("act.delete"), destructive: true });
if (ok) { … }
```

## 16. 시트·모달

**언제**: 입력이 필요한 짧은 작업에 집중시킬 때 — 비밀번호 변경, 일정 수정, 이름 변경.

- 데스크톱(macOS): 제목은 위, 버튼은 **아래 오른쪽에 [취소] [주요]** **[HIG macOS]**. 폰(iOS) 시트는 머리에 취소 · 제목 · 완료를 둘 수 있다.
- 폭 420 (넓은 것 640), 둥글기 20, 진한 유리. 폰에서는 아래에서 올라오는 시트 + 손잡이.
- 시트 위에 시트를 띄우지 않는다. 열리면 첫 입력에 포커스, Esc = 취소.
- 구현: `AppUI.sheet(html, { wide, forced })` → 시트 요소. `.ui-scrim.sheet` + `.ui-sheet` (`.wide`). 버튼 줄은 `.acts` — 오른쪽 정렬, [취소] 다음 [주요].

## 17. 서랍(인스펙터)

캔버스나 목록에서 항목을 고르면 오른쪽에 뜨는 패널 = macOS의 인스펙터.
- 오른쪽에 떠 있음, 폭 520, 둥글기 20, 거의 불투명. 제목 Title 2, 섹션 머리 Subheadline · label-2.
- 폰: 전체 화면 시트 (불투명).
- 안의 카드·콘텐츠 카드는 "안쪽" 변형 (`--fill-4`).
- 서랍은 훑어보기다. 같은 정보를 큰 페이지로 보여줄 때는 그 화면 폭에 맞춰 따로 배치한다 — 좁은 서랍 내용을 그대로 340px 사이드에 넣으면 범례가 잘리고 라벨이 두 줄이 된다.

## 18. 토스트

- 방금 한 일의 결과를 짧게: "게시했어요". 과거형 해요체, **✓·이모지 없이** 앞에 아이콘(`circle-check`, 실패는 `triangle-alert`).
- 되돌릴 수 있으면 "실행 취소" 버튼 (`.ui-btn.plain.small`).
- 4초 뒤 사라짐, 마우스를 올리면 멈춤. 한 번에 하나.
- 오류의 원문(`e.message`)을 그대로 보여주지 않는다 → [writing.md §4](writing.md#4-문구-틀).
- 구현: `AppUI.toast(text, { undo })` → `.ui-toast.ui-glass`. `undo`를 주면 "실행 취소" 버튼이 붙는다.

## 19. 안내줄

페이지 안에 머무는 알림 — "요청 3건이 반영됐어요", "이전에 쓰던 글을 불러왔어요", 다음 할 일 권유.
- `.ui-notice` + `.info` / `.warn`: 아이콘 + 한두 문장 + (선택) 동작 버튼 + 닫기.
- 바탕은 상태 색 10%, 둥글기 `--r-card`.

## 21. 불러오는 중과 진행

| 상황 | 컴포넌트 |
|---|---|
| 버튼을 누르고 기다릴 때 | 버튼 안 스피너 `.is-loading` + "~하는 중…" |
| 영역을 불러올 때 | 0.3초가 넘으면 그 자리에 `.ui-spinner` + 무엇을 불러오는지 한 줄 |
| 얼마나 남았는지 알 때 (업로드·내보내기) | `.ui-progress` (확정형) + "PDF 올리는 중 · 62%" |
| 목표 대비 진행 (기간 목표, 읽음 표시) | `.ui-progress` 변형 — 표시선은 [data-viz.md](data-viz.md#4-차트-종류별-규칙) |

- "불러오는 중…"처럼 모호한 말보다 무엇을 하는지 — "번역하는 중…", "비슷한 항목 찾는 중…".

## 22. 검색

| 검색 | 위치 | 동작 |
|---|---|---|
| **전역 검색** (스포트라이트) | 상단 바 돋보기, `/`, ⌘K / Ctrl+K | 모든 종류(문서·사람·프로젝트·분류)를 한 목록에서. ↑↓ · Enter · Esc |
| **목록 필터** (`.ui-search`) | 목록 페이지의 도구줄 | 그 목록만 좁힘. 입력하는 대로 결과. 주소에 반영(`?q=`) |

- 전역 검색과 목록 필터를 한 입력창에 섞지 않는다.
- 플레이스홀더는 범위를 말한다 — "제목·작성자로 거르기".
- 결과가 없으면 빈 상태 + 조건을 바꾸는 방법.
