# 패턴 — Patterns

컴포넌트를 묶어서 화면과 흐름을 만드는 방법. 새 페이지는 아래 **페이지 틀 6종** 중 하나에서 시작한다.

---

## 1. 앱 구조 — 상단 바 **[결정]**

데스크톱은 위에 붙은 **얇은 반투명 상단 바**(52px)를 쓴다.
macOS 앱의 사이드바 구조도 있지만, 키트는 화면을 넓게 쓰는 상단 바를 기본으로 한다 → [decisions.md](decisions.md#앱-구조).

```
┌──────────────────────────────────────────────────────────────────┐
│ 브랜드 │ 홈 목록1 목록2 사람 │           🔍  [✎ 새 게시물]  🔔  (나) │
└──────────────────────────────────────────────────────────────────┘
  앞: 브랜드  가운데: 내비게이션          뒤: 검색 · 주요 동작 · 알림 · 내 메뉴
```

**규칙**
- 내비게이션 항목은 6개 이하, 짧은 명사. 지금 화면의 항목은 강조(세그먼트 선택 모양)로 표시.
- **주요 동작은 하나** (예: "새 게시물"). 상단 바에서 강조색을 쓰는 유일한 요소.
- 바 뒤로 콘텐츠가 지나간다 (`main { padding-top: var(--top-h) }`). 전체 화면 캔버스는 화면 맨 위부터 그린다.
- 바 바로 아래에 붙는 줄(피드 탭 등)은 불투명 바탕 + 아래로 사라지는 스크롤 가장자리 효과. 글 위에 떠 있는 유리 캡슐을 두지 않는다.
- 폰(≤760px): **iOS 방식** — 위에는 얇은 불투명 한 줄(브랜드·검색·주요 동작·알림·내 아바타), 섹션은 **아래 탭 바** 5개까지. 내 페이지는 오른쪽 위 아바타에서 연다 (탭은 5개까지 **[HIG]**). 홈 인디케이터 영역은 `env(safe-area-inset-bottom)`만큼 띄운다.

## 2. 페이지 틀

### A. 목록 페이지 — 예: 문서 목록, 프로젝트 목록, 나중에 볼 목록

```
[페이지 머리]  Large Title + 부제(Body · label-2)                 [주요 버튼]
[세그먼트]     전체 | 분류별 | 모음
[도구줄]       [목록 필터 ......]  [정렬 ▾] [분류 ▾] [연도 ▾]       312개
[목록]         ─ 행 ─ 행 ─ 행 …  (60개씩, 아래에 "더 불러오기")
```
- 폭 1180. 목록은 `.ui-list` 안의 행 또는 카드 그리드(`auto-fill, minmax(260–320px, 1fr)`).
- 필터 상태는 주소에 남긴다 (`#/docs?q=…`) — 뒤로 가기·공유가 되도록.
- 결과 개수를 도구줄 끝에 회색 숫자로.

### B. 상세 페이지 — 예: 문서, 프로젝트, 분류(주제)

```
‹ 문서                                                     ← 뒤로 (돌아갈 화면 이름)
[머리]  Title 1 제목
        메타 (Callout · label-meta): 작성자 · 출처 · 연도
        태그들                                        [동작 버튼들] [⋯]
┌─────────────────────────────────┬──────────────────┐
│ 본문 1fr                         │ 사이드 340 (고정) │
│  요약 (읽는 폭 672)               │  카드: 관련 일정   │
│  콘텐츠 카드들                    │  카드: 참여한 사람 │
│                                 │  카드: 비슷한 항목 │
└─────────────────────────────────┴──────────────────┘
```
- 폭 1280. 사이드는 `position: sticky`로 상단 바 아래에 붙는다.
- 900px 이하에서는 사이드가 본문 아래로.
- 서랍과 같은 정보를 보여주는 사이드는 같은 렌더 함수를 써도 되지만, 340px 칸에서 범례가 잘리거나 라벨이 두 줄이 되면 페이지에 맞춰 따로 배치한다 ([components.md §17](components.md#17-서랍인스펙터)).
- 일정이 있는 대상(행사·모임)의 상세는 머리가 큰 "히어로"형 (제목 + 일정 + 참가자 묶음) + 할 일 카드 + 세그먼트 탭.
- 사람의 상세는 "프로필"형: 아바타 56 + 이름(Title 1) + 역할·숫자 줄 + 버튼 줄. 모두에게 같은 화면으로 보이고, 내 것이어도 읽기 전용이다 (관리는 내 페이지에서).

### C. 대시보드 — 예: 홈, 내 페이지

- 카드 그리드. 섹션 제목은 Title 2, 카드 제목은 Title 3.
- 숫자 하나를 크게 보여줄 때(이번 달 게시물 수)는 Large Title 강조형 + 아래 설명.
- 홈: 피드(1fr) + 오른쪽 사이드 카드(340, 고정). 피드 위 세그먼트는 상단 바 아래에 붙는다.
- 내 페이지는 지금 할 일(초안, 받은 댓글, 다가오는 일정, 내 콘텐츠 관리)을 모으는 작업 공간이다. 남에게 보이는 모습은 프로필로 잇는다.
- 한 카드에 차트 하나. 차트 규칙은 [data-viz.md](data-viz.md).

### D. 편집 — 예: 새 게시물, 새 프로젝트

```
[머리]  Large Title
┌──────────────────────────────┬──────────────────┐
│ 폼 카드 (최대 820)             │ 도움 사이드 340    │
│  라벨 / 입력 …                 │  중복 경고         │
│                              │  비슷한 항목        │
│              [취소] [게시]     │                  │
└──────────────────────────────┴──────────────────┘
```
- 버튼은 폼 끝에 **취소 왼쪽 · 주요 동작 오른쪽**. 화면 하단에 고정하지 않는다 **[HIG macOS]**.
- 쓰던 내용은 자동으로 임시 저장하고, 돌아오면 안내줄로 알려 준다.
- 폼 규칙은 §6.

### E. 전체 화면 — 예: 그래프, 지도, 캔버스

- 캔버스가 창 전체. 컨트롤은 모두 **떠 있는 유리**: 위 툴바(색 기준·필터·찾기), 왼쪽 아래 범례, 오른쪽 아래 확대·전체 보기, 아래 타임라인.
- 항목을 누르면 오른쪽 서랍(인스펙터). 서랍이 열리면 가운데 정렬 요소는 남은 공간 기준으로 옮긴다.
- 다른 페이지로 가면 캔버스의 계산(배치 시뮬레이션 등)을 멈춘다.
- 폰: 범례는 접히고 서랍은 전체 화면 시트.

### F. 관리 — 관리자

- 세그먼트(멤버 · 분류 · 기간 …) + 표(`.ui-table`) + 표 위의 추가 폼.
- 파괴적 동작(병합·삭제)은 알림으로 확인.

### 공통: 페이지 머리

| 변형 | 쓰는 곳 | 구성 |
|---|---|---|
| 기본 | 목록·대시보드 | Large Title + 부제 |
| 동작 있음 | 목록, 비교 | 기본 + 오른쪽 주요 버튼 |
| 아바타 | 프로필·내 페이지 | 아바타 56 + Title 1 + 메타 + 버튼 줄 |
| 상세 | 상세 페이지 | 뒤로 + Title 1 + 메타 + 태그 + 버튼 줄 |
| 히어로 | 일정이 있는 대상의 상세 | Title 1 + 일정·장소 + 참가자 묶음 + 상태 필 |

제목 크기를 페이지마다 따로 정하지 않는다 — 모두 글자 토큰으로.

## 3. 세 가지 상태 — 모든 화면이 갖춘다

| 상태 | 보여줄 것 | 컴포넌트 |
|---|---|---|
| **빈 상태** | 왜 비었는지 + 다음 할 일 | `.ui-empty` / `.compact` |
| **불러오는 중** | 0.3초 넘으면 스피너 + 무엇을 불러오는지 | `.ui-spinner`, 버튼 `.is-loading` |
| **오류** | 무엇이 안 됐는지 + 어떻게 하면 되는지 + (가능하면) 다시 시도 버튼 | `.ui-empty`(아이콘 `triangle-alert`) 또는 토스트 |

- 조건 때문에 결과가 없는 것("필터에 맞는 항목이 없어요")과 아직 아무것도 없는 것("아직 게시물이 없어요")을 구분한다. 앞의 것은 **조건 바꾸기**, 뒤의 것은 **만들기**를 다음 행동으로 준다.
- 차트는 데이터가 모자라면 빈 문자열을 돌려주지 말고, 언제 보이는지 알려 준다 ("항목이 15개 넘으면 보여요").

## 4. 내비게이션과 주소

- 화면마다 주소가 있다 (`#/doc/<id>`, `#/project/<id>?tab=notes`). 탭·필터 상태도 주소에 남겨 뒤로 가기가 동작하게 한다.
- 다른 화면으로 가는 것은 `<a href>`, 동작은 `<button>`.
- 서랍·시트·전역 검색은 주소를 바꾸지 않는다. Esc나 바깥 누르기로 닫힌다.

## 5. 확인과 되돌리기

```
동작이 되돌릴 수 있나?
 ├─ 예  → 바로 실행 + 토스트 "~했어요 [실행 취소]"         (목록에서 제거, 태그 빼기, 반응 취소)
 └─ 아니오
     ├─ 내 것만 사라짐   → 알림: "~를 삭제할까요?" + 결과 설명 + [취소] [삭제]
     └─ 다른 사람에게 영향 → 알림: 영향을 설명에 적음 ("참가자 모두에게 알림이 가요") + [취소] [실행 동사]
```

- 되돌릴 수 있는 동작은 `AppUI.toast(text, { undo })`, 되돌릴 수 없는 동작은 `AppUI.confirm(…)` ([components.md §15](components.md#15-알림-확인창)·[§18](components.md#18-토스트)).
- 알림을 자주 띄우면 아무도 읽지 않는다. 되돌릴 수 있는 일에는 띄우지 않는다 **[HIG]**.
- 실행 버튼 이름은 제목의 동사와 같게 ("병합할까요?" → [병합]).

## 6. 폼

- 라벨은 위, 도움말·오류는 아래 (§ [components 4](components.md#4-입력)).
- 필수 항목이 대부분이면 선택 항목에만 "(선택)"을 붙인다. 반대면 필수에 표시.
- 같은 줄에 두 입력을 놓을 때는 관련 있는 것만 (날짜 + 시간, 출처 + 연도). 폰에서는 한 줄에 하나.
- 오류는 제출할 때 한꺼번에 보여주고, 첫 오류 입력으로 포커스를 옮긴다. 입력 중에는 형식 검사만.
- Enter: 한 줄 입력에서는 제출, 여러 줄에서는 줄바꿈 (⌘/Ctrl+Enter로 제출).
- 제출 중에는 버튼 `.is-loading`, 성공하면 토스트 + 결과 화면으로.

## 7. 반응형

| 폭 | 바뀌는 것 |
|---|---|
| ≥ 901 | 기본 (2단, 데스크톱 글자) |
| ≤ 900 | 2단 → 1단, 카드 그리드 열 줄어듦 |
| ≤ 760 (폰) | iOS 글자 크기 · 누르기 영역 44 · 위 한 줄 + 아래 탭 바 · 유리 흐림 끔 · 서랍 = 전체 화면 시트 · 팝오버 = 아래 시트 · 표 = 카드형 목록 |

- 기준점은 이 둘만 쓴다 ([foundations.md §4-3](foundations.md#4-3-화면-폭-기준점-결정)).
- 폰에서 필터가 여러 줄로 쌓이면 2열로, 차트 범례는 차트 아래 전체 폭으로, 겹치는 차트 라벨은 숨긴다.
- 마우스 호버에만 있는 정보는 터치에서 탭으로 열린다.

## 8. 키보드

| 키 | 동작 |
|---|---|
| `/` · ⌘K / Ctrl+K | 전역 검색 |
| Esc | 맨 위 층 닫기 (메뉴 → 팝오버 → 시트 → 서랍 순) |
| ↑ ↓ · Enter | 메뉴·검색 결과·목록에서 이동과 실행 |
| ⌘/Ctrl + Enter | 여러 줄 입력에서 제출 |
| Tab | 모달 안에서는 모달 안에서만 돈다 |

- 단축키는 메뉴 항목 오른쪽에 회색으로 보여 준다.
- 포커스 링을 지우지 않는다.
