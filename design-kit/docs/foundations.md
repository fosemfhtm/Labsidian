# 기초 — Foundations

글자 · 색 · 머티리얼 · 레이아웃 · 모서리 · 층 · 모션 · 컨트롤 크기 · 아이콘 · 접근성.
모든 값은 `tokens.css`의 토큰으로만 쓴다. 이 문서가 토큰의 **명세**이고, `tokens.css`가 **구현**이다.

## 1. 글자 · Typography

### 1-1. 글꼴

```css
--font: -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Pretendard Variable", Pretendard, system-ui, sans-serif;
--font-mono: ui-monospace, Menlo, Consolas, monospace;
```
- Apple 기기: SF + Apple SD Gothic Neo. 그 외: Pretendard.
- 숫자를 세로로 맞춰 읽는 곳(표·개수·통계·날짜 열)에는 `font-variant-numeric: tabular-nums` (`.num`).
- 굵기는 400 · 500 · 600 · 700만 쓴다. Ultralight·Thin·Light는 쓰지 않는다 **[HIG]**.

### 1-2. 데스크톱 텍스트 스타일 — macOS **[HIG]**

| 토큰 | HIG 이름 | 크기 / 줄높이 | 굵기 (강조형) | 자간 **[외부: SF 자간표]** | 쓰는 곳 **[결정]** |
|---|---|---|---|---|---|
| `--t-large-title` | Large Title | 26 / 32 | 400 (**700**) | +.008em | 페이지 제목 — 강조형으로 |
| `--t-title1` | Title 1 | 22 / 26 | 400 (**700**) | −.012em | 상세 페이지 제목, 전역 검색 입력 |
| `--t-title2` | Title 2 | 17 / 22 | 400 (**700**) | −.025em | 섹션 제목, 서랍(인스펙터) 제목 |
| `--t-title3` | Title 3 | 15 / 20 | 400 (**600**) | −.015em | 카드 제목, 빈 상태 제목, 목록 묶음 안의 큰 항목 제목 |
| `--t-headline` | Headline | 13 / 16 | **700** | −.006em | 목록 항목 제목, 콘텐츠 카드 작성자, 시트·알림 제목 |

- 기본 13, **최소 10** **[HIG macOS]**. 10보다 작은 글자는 쓰지 않는다 — 아바타가 작아서 글자가 안 들어가면 아바타를 키운다.
- "강조형"은 같은 스타일의 굵은 버전이다. 크기를 키우는 대신 강조형을 쓴다.
- macOS는 Dynamic Type(사용자 글자 크기 설정)을 지원하지 않는다 **[HIG]**. 웹에서는 브라우저 확대(200%)에서 깨지지 않도록 **`rem` 단위**로 정의한다.
- 윈도 저해상도 화면(일반 모니터)에서 Pretendard 10–11px 한글의 선명도는 아직 확인하지 않았다. 프로젝트에서 실제 PC로 보고, 필요하면 보정을 [decisions.md](decisions.md#프로젝트-결정)에 적는다.

| 토큰 | 크기 / 줄높이 | 굵기 | 자간 |
|---|---|---|---|
| `--t-large-title` | 32 / 39 | 700 | +.011em |
| `--t-title1` | 26 / 32 | 700 | +.008em |
| `--t-title2` | 20 / 25 | 700 | −.022em |
| `--t-title3` | 18 / 23 | 600 | −.024em |
| `--t-headline` | 15 / 20 | 600 | −.015em |
| `--t-body` | 15 / 20 | 400 | −.015em |

| `--t-subhead` | 13 / 18 | 400 | −.006em |

- iOS 기본 크기(Large, 본문 17)는 정보가 많은 화면에서 너무 크다 → 사용자가 아이폰에서 글자를 한 단계 줄였을 때의 Apple 공식 크기를 쓴다 [[결정](decisions.md#글자)].
- 최소 11 **[HIG iOS]**.
- 같은 토큰 이름이 화면 폭에 따라 값만 바뀐다. 페이지 코드는 크기를 신경 쓰지 않고 **역할**(제목·본문·메타)만 고른다.
- 폰에서는 유리 흐림을 끈다 (상단 바·탭 바·메뉴가 불투명). 흐림은 폰 GPU 비용이 크다.

### 1-4. 규칙

- **px로 글자 크기를 쓰지 않는다.** `font: var(--t-callout); letter-spacing: var(--tr-callout);` 또는 클래스 `.t-callout`.
- 토큰 묶음: `--t-*` (굵기·크기·줄높이·글꼴 전체) · `--fs-*` (크기만) · `--lh-*` (줄높이) · `--tr-*` (자간). 기본은 `--t-*`이고, 굵기나 줄높이는 그대로 두고 크기만 바꾸는 규칙에서만 `--fs-*`를 쓴다.
- 폰 값은 `tokens.css`의 `@media (max-width: 760px)`가 `--fs-* / --lh-* / --tr-*`만 바꿔서 만든다. 폰 전용 규칙에서 크기를 따로 정하지 않는다.
- 한 화면에서 스타일은 4–5개 정도만 쓴다. 위계를 크기로만 만들지 말고 **굵기와 색(label → label-2 → label-meta)**으로 만든다.
- 여러 줄 문단의 줄높이는 표의 값을 따른다 (13/16). 이 값(1.23)은 한 줄 UI 글자 기준이라 긴 한글 문단에서는 빽빽할 수 있다 — 긴 글의 줄높이는 프로젝트에서 실제 글로 비교해 정하고 [열린 문제](decisions.md#열린-문제)에 적는다.
- 읽는 폭: 긴 글(본문·요약·노트)은 최대 `--readable` (672px) **[외부: readable content guide]**.
- 줄임: 한 줄 제목은 `text-overflow: ellipsis`, 여러 줄은 `-webkit-line-clamp`. 줄인 글은 `title` 속성이나 펼치기로 전체를 볼 수 있어야 한다.

## 2. 색 · Color

### 2-1. 층 구조

```
시스템 색 (red … brown, gray–gray6)   ← tokens.css 안에서만 직접 쓴다
   ↓
의미 색 (label, fill, separator, accent, danger …)   ← 페이지·컴포넌트는 이것만 쓴다
   ↓
컴포넌트 (ui-btn, ui-chip …)
```
예외는 **데이터 색**(사용자가 고르는 색·분류 색·영역 색)뿐이다 → [data-viz.md](data-viz.md).

### 2-2. 의미 색 토큰

| 토큰 | 용도 | 규칙 |
|---|---|---|
| `--label` | 본문·제목 | 기본 글자색 |
| `--label-2` | 보조 글자 (부제, 설명) | |
| `--label-meta` | 날짜·개수·힌트처럼 작지만 **읽어야 하는** 글자 | 4.5:1 보장. 작은 글자에 `--label-3`를 쓰지 말고 이것을 쓴다 |
| `--label-3` | 플레이스홀더, 비활성, 장식 글리프 (빈 별, 꺾쇠) | 읽어야 하는 글자에는 쓰지 않는다 |
| `--label-4` | 아주 옅은 장식 | 글자 금지 |
| `--link-text` | 문장 안의 링크 | **강조색과 같음** — 버튼·선택·링크에 색 하나 |
| `--sys-bg` / `--sys-bg-2` / `--sys-bg-3` | 바탕 / 바탕 위 면 / 떠 있는 면(메뉴·팝오버·시트) | 다크에서 떠 있는 면일수록 밝다 (검정 → `#1c1c1e` → `#2c2c2e`) |
| `--bg-grouped` / `--bg-grouped-2` | 페이지 바탕 / 그 위 카드·목록 | **설정 앱과 같은 값**: 라이트 `#f2f2f7` / `#fff`, 다크 `#000` / `#1c1c1e` |
| `--separator` | 구분선 (0.5px) | 테두리 대신 면 색 차이를 먼저 쓴다 |
| `--fill` ~ `--fill-4` | 컨트롤 바탕(버튼·칩·입력·트랙) | 진한 순서: fill → fill-4. 입력창 fill-4, 버튼·칩 fill-3, 눌림 fill-2 |
| `--accent` / `--on-accent` | 강조색(Indigo)과 그 위 글자 | 아래 2-3 |
| `--danger` | 파괴적 동작, 오류 | red |
| `--success` | 완료 | green |
| `--star` | 별점 | yellow |
| `--warn` | 경고 — 늦게 등록, 마감 임박 | orange |
| `--on-color` / `--on-color-2` / `--on-color-fill` | 색 바탕(배지·타일·아바타·선택 행) 위의 글자·보조 글자·옅은 면 | 흰색 계열. 강조색 바탕 위에는 `--on-accent` |
| `--scrim` / `--scrim-light` / `--scrim-strong` | 알림·시트 뒤 / 전역 검색 뒤 / 사진 확대 뒤를 덮는 막 | |

### 2-3. 강조색 — Indigo **[결정]**

- 라이트 `rgb(97 85 245)` · 다크 `rgb(109 124 255)` **[HIG 시스템 색]**.
- 쓰는 곳: **주요 버튼 하나**, 선택 상태(세그먼트·칩·목록 선택 행), 링크, 포커스 링, 진행 막대.
- 쓰지 않는 곳: 장식, 제목, 아이콘 꾸미기, 카드 테두리, **면의 바탕색**(강조색을 섞은 회색 면을 만들지 않는다).
- 파랑 계열을 하나 더 쓰지 않는다 — 링크도 강조색이다 **[HIG]** "같은 색을 다른 뜻으로 쓰지 않는다".
- 프로젝트가 강조색을 바꿀 때는 시스템 색 하나를 고르고, 링크 대비(4.5:1)를 라이트·다크 카드 위에서 다시 잰 뒤 [decisions.md](decisions.md#프로젝트-결정)에 적는다.

### 2-4. 상태 색

- 빨강 = 위험·오류·안 읽은 알림 배지, 초록 = 완료, 주황 = 경고, 노랑 = 별점.
- **색만으로 상태를 전하지 않는다.** 아이콘이나 글자를 함께 쓴다 (예: 주황 필 안에 "7일 늦게").

### 2-5. 사용자가 고르는 색 — 예외 **[결정]**

사용자가 자기 색(예: 사람 색, 프로필 색)을 **자유롭게** 고르게 할 수 있다 (`<input type=color>`). 그런 색은 테마(라이트·다크·고대비)를 따르지 않는 유일한 색이다. 대신:
- **표시용**으로만 쓴다: 아바타 바탕, 차트 노드·계열, 달력 칸, 범례 점.
- 그 색 위에 글자를 얹을 때(아바타 이니셜)는 **글자색을 자동으로** 고른다 (흰색/검정 중 대비가 큰 쪽).
- 그 색으로 글자를 칠하지 않는다 (대비를 보장할 수 없음). 이름은 `--label`로 쓰고 옆에 색 점을 둔다.
- 회색 계열은 "기타·없음"을 뜻하므로 기본 배정에서 빼고, 고를 때는 경고한다.
- 고대비 설정에서도 바뀌지 않는다는 한계가 있다.

### 2-6. 다크 모드와 고대비

- 테마: **자동(기기 설정) · 라이트 · 다크** — 앱 설정에서 고른다 (`AppUI.setTheme('auto' | 'light' | 'dark')`) **[결정]**. 기본값은 자동.
- 다크는 반전이 아니다. 바탕(base)은 어둡게, 떠 있는 면(elevated: 메뉴·팝오버·시트)은 한 단계 밝게 **[HIG]**.
- 다크 바탕은 **검정**, 카드는 gray6(`#1c1c1e`), 떠 있는 면은 gray5(`#2c2c2e`) — 설정 앱과 같은 단계 **[결정]**.
- `prefers-contrast: more` 또는 `data-contrast="more"`면 시스템 색을 고대비 값으로 바꾸고 구분선을 진하게 한다.
- 대비 기준 **[HIG]**: 17px 이하 글자 **4.5:1**, 18px 이상이거나 굵은 글자 **3:1**. 차트의 선·점 같은 그래픽 요소도 3:1.

## 3. 머티리얼 · Liquid Glass

**유리는 컨트롤·내비게이션 층에만, 콘텐츠에는 쓰지 않는다** **[HIG]**.

| 층 | 머티리얼 | 해당 요소 |
|---|---|---|
| 내비게이션·컨트롤 | 유리 (`.ui-glass`) | 상단 바, 캔버스(지도·그래프) 위 떠 있는 컨트롤(툴바·범례·확대 버튼) |
| 글이 많은 떠 있는 면 | 진한 유리 (`.ui-glass.strong`) | 메뉴, 팝오버, 알림, 시트, 토스트, 전역 검색 |
| 인스펙터 | 거의 불투명 (92%) | 서랍 — 긴 글을 읽어야 하므로 |
| 콘텐츠 | **불투명 면** | 카드, 콘텐츠 카드, 목록, 표 |

- 유리에는 색이 없다. 색은 **주요 버튼 하나의 바탕**에만 쓴다 (`.ui-btn.glass.prominent`).
- 바 뒤로 콘텐츠가 지나갈 때는 바 전체를 칠하지 말고, 콘텐츠와 겹치는 가장자리에 **스크롤 가장자리 효과**(그라데이션 페이드)를 쓴다.
- 밝은 콘텐츠 위의 투명 유리(캔버스 위)는 35% 어둡게 깐다 (`--dim`) **[HIG]**.
- `prefers-reduced-transparency: reduce` 또는 앱 설정 "투명도 줄이기"면 불투명 `--sys-bg-3`로 바뀐다 (토큰이 처리).
- 폰(≤760px)에서는 흐림을 끄고 불투명 면으로 그린다 (§1-3).
- WebGL·캔버스 위의 큰 `backdrop-filter`는 느리다. 캔버스 위에는 작은 컨트롤에만 쓴다.

웹 구현값(틴트·흐림·반사·테두리 하이라이트)은 `tokens.css`의 `--glass-*` 토큰에 있다.

## 4. 레이아웃과 간격

### 4-1. 간격 — 4pt 기반 **[결정]**

| 토큰 | 값 | 주로 쓰는 곳 |
|---|---|---|
| `--s-1` | 4 | 아이콘–글자 사이, 촘촘한 묶음 |
| `--s-2` | 8 | 컨트롤 사이, 칩 사이 |
| `--s-3` | 12 | 카드 안 요소 사이, 테두리 있는 컨트롤 주변 **[HIG ~12pt]** |
| `--s-4` | 16 | 카드 안쪽 여백, 폰 화면 여백 |
| `--s-5` | 20 | 데스크톱 화면 여백 |
| `--s-6` | 24 | 섹션 사이, 카드 사이, 테두리 없는 컨트롤 주변 **[HIG ~24pt]** |
| `--s-8` | 32 | 큰 섹션 사이, 빈 상태 위아래 |
| `--s-11` | 44 | 페이지 머리와 본문 사이 |

### 4-2. 폭과 단 **[결정]**

| 항목 | 값 |
|---|---|
| 화면 여백 `--margin` | 데스크톱 20 · 폰 16 **[외부: UIKit 기본]** |
| 콘텐츠 최대 폭 | 기본 1180 · 넓은 페이지(상세) 1280 |
| 읽는 폭 `--readable` | 672 |
| 2단 레이아웃 | 본문 `1fr` + 사이드 **340** |
| 폼 최대 폭 | 820 |

### 4-3. 화면 폭 기준점 **[결정]**

| 기준점 | 바뀌는 것 |
|---|---|
| **≤ 760px** | 폰: iOS 글자 크기, 아래 탭 바, 서랍이 전체 화면 시트로, 팝오버는 시트로 |
| **≤ 900px** | 2단 → 1단 (사이드가 본문 아래로) |

이 둘만 쓴다. 다른 기준점이 꼭 필요하면 [decisions.md](decisions.md#프로젝트-결정)에 이유와 함께 적는다.
특정 칸의 폭에 따라 바뀌어야 하는 배치(사이드 카드 안의 배치처럼)는 화면 폭 대신 **컨테이너 쿼리**(`@container`)로 만든다.
터치 여부는 폭이 아니라 `@media (pointer: coarse)`로 판단한다 (누르기 영역 44).

### 4-4. 배치 규칙 **[HIG]**

- 중요한 것을 위쪽·앞쪽(왼쪽)에 둔다.
- 관련된 것끼리 묶는다: 빈 공간 → 면(카드) → 구분선 순으로 먼저 쓴다.
- 처음에는 적게 보여주고 필요할 때 펼친다 (펼치기 삼각형, "더 보기", 서랍).
- macOS: **중요한 컨트롤을 창 아래쪽 가장자리에 두지 않는다.** 웹 페이지에서 화면 하단 고정 버튼 바를 만들지 않는다 (폰 시트 안은 예외).

## 5. 모서리 — 동심원 규칙

**안쪽 반지름 = 바깥 반지름 − 그 사이 여백** **[HIG]**. 예: 메뉴 14 · 안쪽 여백 6 → 메뉴 항목 8.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--r-sheet` | 20 | 시트, 모달, 알림, 전역 검색, 서랍 |
| `--r-card` | 20 | 카드, 목록 묶음 (설정 앱의 그룹처럼 크게) |
| `--r-popover` | 14 | 메뉴, 팝오버, 검색 결과 목록 |
| `--r-control` | 10 | 버튼(보통), 입력창, 세그먼트 바깥 |
| `--r-control-sm` | 8 | 작은 버튼, 메뉴 항목, 세그먼트 안쪽, 툴팁 |
| `--r-xs` | 4 | 체크박스, 키 표시(kbd), 얇은 표시선 |
| `--r-full` | 999 | 칩, 태그, 필, 배지, 아바타, 상단 바의 캡슐 버튼 |

이 여섯 단계(20 · 14 · 10 · 8 · 4 · 완전) 밖의 값은 쓰지 않는다.
막대그래프의 트랙처럼 높이가 아주 작은 요소는 높이의 절반(`border-radius: 999px`)으로 둥글린다.

## 6. 층과 그림자

| 층 | 바탕 | 그림자 |
|---|---|---|
| 바탕 | `--bg-grouped` | 없음 |
| 콘텐츠 (카드·목록) | `--bg-grouped-2` | `--shadow-1` (라이트: 아주 옅게 · 다크: 없음 — 면 색 차이로 구분) |
| 카드 안 | **회색 상자를 두지 않는다** — 항목 사이는 0.5px 구분선(`--separator`). 서랍·시트 안의 카드만 `--fill-4` | 없음 |
| 떠 있는 것 (메뉴·팝오버·시트·알림) | 유리 strong | `--shadow-2` |

그 밖의 그림자 토큰: `--shadow-seg` (세그먼트의 선택 칸), `--shadow-knob` (스위치 손잡이), `--text-shadow-on-color` (색 바탕 위 글자).

- 테두리로 면을 나누지 않는다. 면 색 차이와 **넓은 간격**(카드 사이 24)으로 나눈다. 카드 안에서는 구분선으로 나눈다.
- 점선 테두리는 "아직 비어 있는 자리"(아직 채워지지 않은 항목, 파일 놓는 곳)에만 쓴다.
- 색 띠(카드 왼쪽 세로줄)로 종류를 구분하지 않는다 → 아이콘이나 필로 구분한다.

## 7. 모션

HIG는 시간·곡선 수치를 주지 않는다 → **[결정]**

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--dur-fast` | 150ms | 누름·호버·색 바뀜 |
| `--dur` | 300ms | 시트·서랍·알림 등장, 화면 전환 |
| `--ease` | `cubic-bezier(.2,.8,.2,1)` | 감속 |

- 자주 하는 동작(탭 전환, 목록 필터)은 애니메이션하지 않는다 **[HIG]**.
- 움직임만으로 정보를 전하지 않는다 **[HIG]**.
- `prefers-reduced-motion`이면 이동·확대 대신 페이드로, 물리 애니메이션(그래프 배치 등)은 즉시 배치 (토큰이 시간을 1ms로 줄임).

## 8. 컨트롤 크기와 누르기 영역

| | 기본 | 최소 | 근거 |
|---|---|---|---|
| 데스크톱 | **28 × 28** | 20 × 20 | **[HIG macOS]** |
| 폰·터치 | **44 × 44** | 28 × 28 | **[HIG iOS]** |

| 컨트롤 높이 **[결정]** | 데스크톱 | 폰 |
|---|---|---|
| 작은 (`.small`) — 표·카드 안 보조 동작 | 22 | 44 |
| 보통 — 기본 버튼, 입력창, 세그먼트 | **28** | 44 |
| 큰 (`.large`) — 로그인, 빈 상태의 다음 행동 | 34 | 50 |

- 토큰 `--hit`이 데스크톱 28 · 터치 44로 바뀐다. 컨트롤은 `min-height: max(var(--hit), …)` 꼴로 쓴다.
- 눈에 보이는 크기가 작아도 누르는 영역은 넓힌다 (padding이나 `::after`로).
- 컨트롤 사이 간격: 테두리(바탕) 있는 컨트롤 ~12, 없는 컨트롤 ~24 **[HIG]**.

## 9. 아이콘

- **Lucide** (`<i data-lucide="name" class="ic">`), 선 굵기 2, 크기는 옆 글자의 1.15em.
- 아이콘만 있는 버튼은 반드시 `aria-label`과 `title`(툴팁)을 단다.
- UI(버튼·제목·메뉴·토스트·빈 상태)에 **이모지를 쓰지 않는다.** 사용자가 쓴 글 안의 이모지는 그대로 둔다.
- 같은 뜻에는 같은 아이콘: 쓰기 `pen-line` · 삭제 `trash-2` · 편집 `pencil` · 추가 `plus` · 더 보기 `ellipsis` · 닫기 `x` · 검색 `search` · 알림 `bell` · 완료 `circle-check` · 경고 `triangle-alert` · 나중에 볼 목록에 추가 `bookmark-plus` · 댓글 `message-circle` · 번역 `languages`.
- SF Symbols는 웹에서 쓸 수 없다 (복사·비슷하게 다시 그리기 포함) → [decisions.md](decisions.md#아이콘과-라이선스).
