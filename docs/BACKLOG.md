## 할 일

### 실시간 반영(폴링) 후 그래프가 최신 데이터를 따라가지 않음

- **증상:** 페이지를 열어 둔 채로 다른 탭·멤버·MCP의 변경이 폴링(`/api/changes`)으로 들어오면, `store.js`의 `pull()`이
  `buildDataset()`으로 `window.LAB`를 새 객체로 다시 만들어요. 그래프(`graph.js`)는 `start()` 때 만든 graphology
  그래프와 조회표를 계속 써서, 새로고침 전까지 새 다이어리·새 읽은 사람이 지도에 안 나타나요. 옛 객체를 보는 탓에
  다른 동작도 어긋날 수 있어요.
- **재현:** A 탭에서 그래프를 연다 → B 탭(다른 멤버)에서 A가 안 읽은 논문에 다이어리를 게시 → A 탭에 3초 안에 알림은
  오지만 지도에는 그 연결이 없어요.
- **할 일:**
  - `graph.js`가 `lab:data` 이벤트를 받아 노드·엣지(새 논문, 새 읽은 사람, 삭제)를 갱신하기. 위치·줌·선택 상태는 유지.
  - 다른 페이지 모듈 중에 `window.LAB`를 따로 들고 있는 곳이 있는지 점검.
- **참고:** 같은 원인으로 `app.js`의 조회표(`P`/`T`/`PA`/`R`)와 `_hay`/`_last`가 어긋나 '논문' 탭이 비던 문제는
  `lab:data`(`store.js` `pull()`) + `app.js` `index()`로 고쳤어요 (2026-10-04).

### 서버 인증의 남은 부분 (2026-10-06)

로그인·세션·비밀번호·MCP 토큰은 서버(`scripts/serve.py`)가 확인해요. 아직 남은 것:

- **콘텐츠 쓰기는 멤버를 믿어요.** 브라우저는 레코드를 통째로 보내고(`POST /api/state`), 서버는 계정 레코드만 검사해요
  (남의 계정·역할·비밀번호는 못 바꿈). 로그인한 멤버가 개발자 도구로 남의 다이어리나 댓글 레코드를 바꾸는 건 막지 못해요.
  막으려면 브라우저 쓰기도 MCP처럼 명령(`/api/ops`)으로 보내고 서버가 `store.js` 규칙으로 처리해야 해요.
- **MCP 토큰을 사이트에서 발급하기.** 지금은 관리자가 서버에서 `serve.py --token <이름>`으로 만들어요. 내 페이지에서
  멤버가 직접 만들고 지울 수 있으면 좋아요(토큰 목록·마지막 사용 시각).
- **HTTPS.** 연구실 서버 앞에 Caddy 같은 리버스 프록시를 두고 인증서를 붙이기(쿠키에 `Secure`는 `X-Forwarded-Proto: https`일 때 붙어요).
