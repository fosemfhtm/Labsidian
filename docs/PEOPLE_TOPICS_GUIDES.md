# 사람 · 주제 · 핵심 논문 가이드 — 기획서

사람 페이지를 "정보를 보여주는 연구자 소개"로 다시 만들고, 분야·방법론을 독립 페이지로 떼어 내고,
연구실이 함께 만드는 핵심 논문 가이드를 스터디와 엮는다. (2026-10, 데모 인물로 예시)

## 0. 원칙

- **실제 기록만 보여준다.** 성격 유형·능력치를 지어내지 않는다. 모든 그림은 다이어리·태그·지도·함께 읽은 논문에서 나온다.
- **별점은 신호로 쓰지 않는다.** 가져온 다이어리의 별점 73%가 3점(양식 기본값)이라 "좋은 논문"을 고르는 데 쓸 수 없다.
  대신 읽은 사람 수, 👍·👀 반응, 질문·댓글 수, 스터디에서 다뤘는지, 가이드에 들어갔는지를 쓴다.
  (사이트의 쓰기 양식은 이미 별점을 직접 고르게 되어 있어서, 앞으로 쓰는 다이어리는 별점이 의미를 갖는다.)
- **관리자 일을 늘리지 않는다.** 새로 생기는 이름·묶음은 자동으로 정해지고, 관리자는 원할 때만 고친다(관리자 MCP).
- **추천은 없다.** 사람 페이지는 정보만 보여준다.
- **모든 쓰기는 작업 요청(op)** — 관리자·멤버의 AI(MCP)도 같은 방식으로 쓰고, 나중에 외부 DB로 옮겨도 그대로다.

## 1. 역할 나누기: 내 페이지 vs 사람 페이지

| | 내 페이지 (`#/me`) | 사람 페이지 (`#/person/<id>`) |
|---|---|---|
| 한마디로 | 내 작업 공간 | 연구자 소개 |
| 보는 사람 | 나 | 연구실 누구나 |
| 시간 | 이번 학기, 시간에 따른 변화 | 지금까지 쌓인 전체 모습 |
| 내용 | 작성률·목표·연속 작성, 작성 캘린더, 읽을 목록, 받은 댓글, 내 리뷰 관리, 초안, docx, 관심사 변화 | 역할 한 줄, 숫자 세 칸, 연구 지형 꽃잎 차트(지역↔방법론), 세부 분야 막대, 비슷한 사람, 리뷰 |

- 작성률·목표·연속 작성처럼 의무와 관련된 숫자는 사람 페이지에 넣지 않는다(감시받는 느낌).
- 내 사람 페이지를 열면 "다른 사람에게는 이렇게 보여요 · 내 페이지로 →", 내 페이지에는 "내 프로필 보기".

## 2. 연구 지형 축: 지도의 "큰 지역" 8개

분야·방법론 태그는 계속 늘어나서 축으로 고정하기 어렵다. 대신 그래프의 지도 영역을 한 단계 더 묶은 **큰 지역**을 축으로 쓴다.

- `build_map.py`: 지금의 작은 영역(f, ~62) → 큰 영역(c, ≤14) 위에 **큰 지역(a, ≤8)** 을 하나 더 만든다.
  큰 영역들의 지도 중심을 Ward로 8개 묶는다 → 항상 지도에서 이웃한 영역끼리 묶인다.
- 논문마다 `a`(큰 지역)가 붙는다. 연구실 전원이 같은 8개 축을 쓰므로 사람끼리 비교할 수 있다(FM 선수 비교).
- **이름은 자동.** 큰 지역 이름 = 그 안의 큰 영역 중 가장 큰 두 개의 이름(관리자가 붙인 이름이 있으면 그 이름) — 관리자가 할 일이 없다.
  원하면 관리자가 `admin_name_cluster`로 큰 지역에도 이름을 붙일 수 있고, 지도를 다시 만들어도 논문을 따라간다.
- 분야가 늘어나도 새 논문이 지도에 놓이면 자동으로 반영된다. 지도를 다시 만들면 경계가 조금 바뀔 수 있다(지금 모습만 보여주므로 괜찮다).
- 리뷰가 적은 사람(15편 미만)은 연구 지형 대신 "아직 쌓이는 중"을 보여준다.

## 3. 사람 페이지

위에서 아래로:

1. **머리** — 아바타, 이름, 학기들. **역할 한 줄**: "가장 많이 읽는 큰 지역 × 가장 많이 쓰는 방법론"(예: "교통 안전 지역 · 통계형").
2. **숫자 세 칸** — 리뷰한 논문(+ 주별 추이선), 함께 읽은 논문, 참여한 스터디. (평균 별점은 뺀다)
3. **연구 지형 꽃잎 차트(로즈)** — 축마다 꽃잎 하나, 꽃잎 넓이 = 비중, 점선 호 = 연구실 평균. 한 줄 요약: "연구실 평균보다 ○○ 지역 2.6배". 옆에 축별 % 목록.
   - [변경 2026-10-03] 처음엔 레이더였는데, 한두 지역만 읽는 사람은 모양이 거의 직선이 됐다(데모 페르소나 대부분). 레이더는 축 값이 고루 있을 때만 모양이 생김 → 한 지역에 몰려도 '큰 꽃잎 하나'로 보이는 로즈로 바꿈. 지역 축은 지도에서 놓인 방향 순서(위에서 시계 방향)라 이웃 꽃잎 = 지도에서 이웃한 지역.
   - **지도 지역 ↔ 방법론** 세그먼트 컨트롤로 전환(연구실 상위 7개 방법론 + 기타 = 고정 8축, 논문 하나에 방법론이 둘이면 반씩). 선택은 기억되고 사람 목록·사람 페이지·비교가 같이 바뀜.
4. (방법론 띠는 꽃잎 차트의 방법론 전환으로 대체)
5. **세부 분야** — 상위 6개 + 기타를 편수 막대로(그 사람 색 — 지도 지역 색은 꽃잎 차트 몫이라 섞지 않음). 줄을 누르면 주제 페이지.
6. **관심사가 비슷한 사람** — 아바타·이름·% 칩 한 줄(읽은 분야 기준). 누르면 두 사람 비교 화면.
   - [변경 2026-10-03] 궤도 그림은 거리 말고는 방향·타원에 의미가 없고 이름이 목록과 두 번 나와서 뺌. 왜 비슷한지는 비교 화면이 보여준다.
7. **버튼** — 그래프에서 보기, **비교하기**.
8. **리뷰** — 지금처럼 학기 선택 + 전체 리뷰(사람 페이지 전체 화면에서).

## 4. 사람 비교 (`#/compare/<a>/<b>`)

FM 선수 비교처럼:
- 좌우 머리 카드(각자의 색): 역할 한 줄, 숫자 세 칸.
- 두 사람의 꽃잎 차트를 나란히(같은 눈금), 아래에 축마다 좌우 막대 + 숫자(큰 쪽 굵게). 지역↔방법론 전환.
- **둘 다 읽은 논문** 목록(같은 논문에 대한 두 사람의 리뷰로 바로).
- 상대 고르기: 비교 화면 위의 사람 선택. 사람 페이지의 "비교하기"는 보는 사람이 멤버면 "나와 비교", 아니면 가장 비슷한 사람과.

## 5. 사람 목록 페이지 (`#/people`)

- 맨 위 "연구실 전체 분야·방법론" 막대는 주제 페이지로 옮긴다.
- **맨 위 "연구실 전체" 카드**: 연구실 전체 꽃잎(크게) + 축별 목록(색·이름·비중·편수) + 지도 지역 ↔ 방법론 전환. 범례·전환·기준점·고르기를 한 카드가 맡는다.
- **아래는 사람 카드**: 꽃잎 + 이름만. 모두 같은 축·같은 색이라 카드만 훑어도 누가 어디를 읽는지 보인다.
- **고르기**: 위 목록에서 항목을 누르면 모든 꽃잎에서 그 축만 진해지고, 사람 카드가 그 비중 순으로 정렬되며 "38% · 21편"이 붙는다. 다시 누르면 원래대로("누구에게 물어볼까"를 꽃잎 위에서).
   - [변경 2026-10-03] 사람 × 지역 매트릭스 → "누구에게 물어볼까" 목록 → 둘 다 뺌. 매트릭스는 한눈에 안 읽혔고, 목록은 시각화가 약했다. 연구실 전체 지형은 그래프 뷰가 맡고, 여기서는 사람 단위 비교만.
   - 카드에 있던 것들의 행방: 역할 한 줄 → 사람 페이지 머리에만 · 관심사 팔레트 → 없앰(꽃잎과 중복) · 분야 막대 → 사람 페이지 세부 분야 · 주별 추이 → 사람 페이지 "리뷰한 논문" 칸 배경 · 가장 비슷한 사람 → 사람 페이지 비슷한 사람 칩.

## 6. 주제 페이지 (논문 페이지 안의 탭)

메뉴를 늘리지 않고 **논문 페이지에 [논문 목록 | 분야·방법론 | 가이드] 탭**.
- **분야·방법론**: 두 축의 막대(사람 페이지에서 옮겨 옴). 누르면 주제 상세.
- **주제 상세(`#/topic/<tid>`)** — 지금 서랍 내용의 전체 화면판: 숫자, 누가 많이 읽었나, 같이 쓰인 방법론/분야,
  **많이 읽힌 논문**(읽은 사람 수·반응 순, 별점 대신), 최근 읽은 논문, **이 태그가 붙은 가이드**.
- 태그를 누르면 지금처럼 서랍이 열리고, 서랍에 "주제 페이지 →".

## 7. 핵심 논문 가이드 (`#/guides`, `#/guide/<id>`)

AdvancedML 같은 주제별 핵심 논문 목록을 연구실이 함께 만든다. 정적인 목록과 다른 점: 누가 읽었는지, 내가 어디까지 읽었는지, 스터디에서 다뤘는지가 보인다.

- **가이드** = 제목, 설명, 태그 여러 개(분야·방법론), 만든 사람, **구간**(예: 기초 / 핵심 / 최신), 논문 목록.
- **논문 항목** = 연구실 논문이나 외부 논문(링크·DOI·arXiv·제목으로 추가, 정보 자동), "왜 핵심인지" 한 줄, 추가한 사람, 👍.
- **권한**(기본값): 누구나 논문 추가·👍. 가이드 정보·구간·순서·남의 항목 빼기는 만든 사람과 관리자. 자기 항목은 자기가 고치거나 뺀다.
- **진행도**: 그 논문에 다이어리를 쓰면 자동 ✓ — "12편 중 5편". 연구실에서 몇 명이 읽었는지 아바타로.

### 스터디와 양방향

| 방향 | 동작 |
|---|---|
| 가이드 → 스터디 | 항목마다 "스터디 열기"(논문이 채워진 스터디 만들기). 가이드 위의 "다음 스터디"는 아직 아무도 안 읽은 항목 중 👍가 많은 것을 골라 준다. |
| 스터디 → 가이드 | 스터디 페이지에 "가이드에 추가": 공통 논문, 멤버들이 가져온 관련 논문을 원하는 가이드·구간에 한 번에 넣는다. |
| 연결 표시 | 가이드 항목에 "스터디에서 다룸 · 날짜 · 정리 노트 →"(그 논문으로 열린 스터디가 있으면). 스터디 페이지에 "이 논문이 들어 있는 가이드". |
| 후보 | 스터디 목록의 "같이 읽고 싶어하는 논문"에 가이드 항목 중 아직 아무도 안 읽고 👍 2개 이상인 것도 나온다. |

### 그 밖의 연결
- **읽을 목록**: 항목마다 📚, 가이드 위의 "남은 논문 전부 읽을 목록에".
- **주제 페이지**: 태그가 붙은 가이드 목록, "새 가이드 만들기".
- **MCP**: `list_guides`, `get_guide`, `create_guide`, `add_guide_item`, `vote_guide_item` — "교통 예측 가이드 초안 만들어줘" 같은 일을 AI가 하되, 반영은 사람이 확인한 것만(초안은 만든 사람의 가이드로 들어가 다른 멤버가 다듬는다).

## 8. 데이터 · 작업 요청

- `map.json` / `data.js`: 클러스터에 `level: "a"`, 논문에 `a`. 큰 영역(c)에 `parent: "a…"`.
- Store 레코드(서버 SQLite): `guides` 컬렉션 — `{ id, title, desc, tags[], owner, sections[{id,title}], items[{id, section, paperId | meta, key, note, by, at, votes[]}], createdAt, updatedAt }`.
- 작업 요청: `guide.create` · `guide.update` · `guide.addItem` · `guide.removeItem` · `guide.vote` · `guide.moveItem`(+ 기존 작업들).

## 9. 하지 않는 것 (지금은)

- 성격 유형·능력치 카드, 사람 추천, 학기 Wrapped(나중에 후보).
- 가이드 승인 흐름(누구나 추가 + 만든 사람이 정리하는 방식으로 시작).
