# 글쓰기 — Writing

화면의 모든 글자에 대한 규칙. 문구는 i18n 키(`t("key")`)로만 넣는다 (§7).

---

## 1. 목소리

- **차분하고 짧게.** 연구실 동료에게 말하듯, 꾸밈 없이.
- **문장은 해요체.** "다이어리를 게시했어요", "조건에 맞는 논문이 없어요". 합니다체·반말은 쓰지 않는다.
- **라벨은 명사형.** 버튼·메뉴·탭·표 머리·입력 라벨·필 — "저장", "참가자", "7일 늦게".
- 한 덩어리 안에서 섞지 않는다: 빈 상태 문장은 해요체("아직 없어요"), 표 칸의 짧은 상태값만 명사형("없음").
- 사용자를 탓하지 않는다: "잘못 입력했어요" 대신 "비밀번호가 맞지 않아요".
- 느낌표·이모지·✓를 쓰지 않는다. 기쁨은 문장이 아니라 결과로 보여 준다.

## 2. 용어집

| 쓴다 | 쓰지 않는다 | 뜻 |
|---|---|---|
| **다이어리** | 리뷰, 후기, 글 | 멤버가 논문을 읽고 쓴 기록. 세는 단위 "편" |
| 논문 | 페이퍼 | |
| 스터디 | 모임(스터디 안의 한 번은 "회") | 여러 사람이 같은 논문을 읽고 모이는 일 |
| 핵심 논문 가이드 (짧게: 가이드) | 커리큘럼 | 연구실이 함께 만드는 읽을 논문 순서 |
| 읽을 목록 | 북마크, 찜 | 나중에 읽을 논문 |
| 분야 | 도메인, 주제 태그 | 교통 문제 (태그 종류) |
| 방법론 | 메서드, 기법 | 쓰는 기법 (태그 종류) |
| 지도 영역 | 클러스터 | 그래프에서 내용이 비슷한 논문이 모인 곳 |
| 학기 | 텀 | |
| 메모 | Memo (critic) | 다이어리의 한계·생각 칸 |
| 질문 · 정리 노트 | | 스터디의 질문 보드, 끝난 뒤 정리 |
| 멤버 · 관리자 | 유저, 어드민 | |
| 먼저 쓰고 보기 | 블라인드 | 내 다이어리를 쓰기 전에는 남의 것을 가리는 스터디 설정 |

- 다이어리 양식의 칸 이름(Problem · Method · Result · Contribution)은 연구실 양식이라 영어 그대로 둔다.
- PDF · DOI · AI(MCP)는 그대로 쓴다.
- 사람을 부를 때: "{이름} 님" — **님 앞을 띄운다** (지금 `{a}님이` / `{a} 님이`가 섞여 있음).

| Delete | **삭제** | 지우기 | 데이터가 사라질 때만 |
| Remove | **제거** | 빼기, 목록에서 빼기 | 목록·묶음에서만 빠지고 원본은 남을 때 |

| Post | **게시** | 게시하기, 남기기, 올리기 | 다이어리·댓글·질문을 남에게 보이게 할 때 |
| Cancel | **취소** | | |

## 4. 문구 틀

| 종류 | 틀 | 예 |
|---|---|---|
| **확인창 제목** | ~할까요? | 이 다이어리를 삭제할까요? |
| **확인창 설명** | 결과를 한두 문장 | 질문과 정리 노트도 함께 지워지고 되돌릴 수 없어요. |
| **확인창 버튼** | 취소 + 제목의 동사 | [취소] [삭제] |
| **토스트 (성공)** | ~했어요 | 게시했어요 · 읽을 목록에 추가했어요 |
| **토스트 (실패)** | ~하지 못했어요. + 할 일 | 저장하지 못했어요. 잠시 뒤 다시 시도해 주세요. |
| **빈 상태 (처음)** | 아직 ~가 없어요. + ~해 보세요. | 아직 정리 노트가 없어요. 모임이 끝나면 누구든 정리해 보세요. |
| **빈 상태 (조건)** | ~에 맞는 ~가 없어요. + 조건 바꾸기 | 조건에 맞는 논문이 없어요. 필터를 줄여 보세요. |
| **빈 상태 (작게)** | 한 문장 | 새 알림이 없어요 |
| **오류 (입력)** | 무엇이 + 어떻게 | 비밀번호는 6자 이상이어야 해요 |
| **오류 (시스템)** | 무엇이 안 됐는지 + 할 일 | 서버에 연결하지 못했어요. 새로 고침해 보세요. |
| **진행** | ~하는 중… | 번역하는 중… · 비슷한 논문 찾는 중… |
| **플레이스홀더** | 예시 또는 범위 | 예: 세미나실, Zoom · 논문·사람·스터디 검색 |
| **권유** | ~볼까요? | 이번 주 논문 다이어리를 써 볼까요? |

- 빈 상태의 두 문장은 마침표로 잇는다. " — "로 잇지 않는다.
- 개발자용 정보(파일 이름, `scripts/serve.py`, 오류 원문 `e.message`)는 화면에 쓰지 않고 콘솔에 남긴다.
- 확인창의 결과 설명은 제목에 붙이지 않고 `message`에 넣는다.

## 5. 표기

**날짜와 시간** **[결정]**

| 상황 | 표기 |
|---|---|
| 방금 일어난 일 (알림·피드·댓글) | 방금 · 5분 전 · 3시간 전 · 어제 · 6일 전 → 7일부터는 날짜 |
| 날짜 (올해) | 10월 2일 |
| 날짜 (다른 해) | 2025년 10월 2일 |
| 요일이 중요할 때 (스터디 일정) | 10월 3일 (토) 14:00 |
| 월 단위 | 2026년 10월 |
| 표·내보내기·정렬용 | 2026-10-02 |
| 마감 | D-3 · 오늘 · 3일 지남 |
| 등록 시점 | 7일 늦게 · 2일 미리 |

- 상대 시간 함수는 하나만 쓴다 (지금 `home.js`와 `auth.js`에 다른 구현이 둘 있음). 날짜는 `Intl.DateTimeFormat`으로.

**숫자와 단위**
- 천 단위 쉼표: 1,234. 숫자 열·개수는 `tabular-nums`.
- 세는 단위: 논문·다이어리 **편**, 사람 **명**, 질문·댓글·태그 **개**, 스터디 회차 **회**, 학기 **학기**.
- 숫자와 단위는 붙인다: 12편, 3명. 라벨과 숫자는 띄운다: 다이어리 12편, 질문 3.

**문장 부호**
- 말줄임: "…" (U+2026) 한 글자. "..." 금지.
- 나열: 가운뎃점 "·" (논문·저자·키워드).
- 인용: “ ” (곧은따옴표 " " 대신).
- 범위: 3–5 (줄표 en dash).

## 6. 영어 (EN)

- 모든 문구는 KO/EN 두 벌. 영어는 Apple 영어 UI를 따른다: 버튼·메뉴·제목은 **Title Case** ("Write Diary", "Edit Schedule…"), 문장은 Sentence case.
- 용어 대응: 다이어리 = **diary**, 스터디 = study, 핵심 논문 가이드 = core-paper guide, 읽을 목록 = reading list, 분야 = field, 방법론 = method, 지도 영역 = map region.
- 상대 시간: "just now · 5 min ago · 3 hr ago · yesterday".

## 7. i18n 규칙

- 문구는 `i18n.js`의 사전(또는 모듈의 `I18N.extend`)에 넣고 `t("key", {vars})`로 쓴다. 코드에 한국어·영어 문장을 직접 쓰지 않는다 (지금 `"(untitled)"`, `"export failed"`, `lang === "ko" ? … : …` 같은 곳이 남아 있음).
- 키는 `모듈.뜻` (`st.delQ`, `rl.empty`). 공통 동작어는 `act.*`로 한 번만 정의하고 재사용한다 — `act.save`, `act.delete`, `act.cancel` …
- 변수 자리는 `{name}`. 조사가 바뀌는 곳은 "(으)로", "을(를)" 대신 문장을 바꿔 피한다.
- 쓰지 않는 키는 지운다.
