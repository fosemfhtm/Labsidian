규칙을 바꿀 때는 이 문서에 날짜·결정·이유를 먼저 적고, 해당 규칙 문서를 고친다.

## 2026-10-22 — 정기 스터디를 가이드에서 분리

| 결정 | 이유 |
|---|---|
| 정기 스터디를 **따로 된 개체**(`groups`)로 둠. 가이드의 "모임으로 진행"·`guide.group`·`study.guideId`는 없앰 → `study.groupId` | 10-03에는 "가이드 = 리딩 리스트 + 일정"으로 묶었으나, 실제 연구실 정기 스터디(최신 AI 논문과 교통 적용)는 주제가 매번 바뀌어 "핵심 논문 가이드" 안에 들어가는 것이 어색했음. 사용자가 정기 스터디가 가이드 화면으로 가는 것을 이상하다고 봄 |
| 정기 스터디는 **스터디 탭**에 있음: 목록 위 카드, `#/group/<id>`(일정·장소·참여자·회차), `#/group/new` | 사람들이 모임을 찾는 곳은 스터디. 가이드는 논문 탭의 큐레이션 목록으로만 남음 |
| 회차가 끝나도 논문이 가이드에 자동으로 쌓이지 않음(`harvest`·항목 `from` 없앰). 다음 회차 만들기에 가이드 추천 논문 칩도 없음 | 정기 스터디에 목록이 따로 없으니 쌓일 곳이 없음. 다룬 논문은 회차 목록 자체가 기록. 원하면 스터디 페이지의 "가이드에 추가"로 직접 넣음 |
| 예전 데이터는 불러올 때 한 번 옮김(`store.js` `ensureSeed`): 모임이 켜진 가이드 → `groups`, 그 회차 → `groupId`, 알림 `guideSession`/`guideJoin` → `groupSession`/`groupJoin` | 서버·데모·브라우저 저장소 어디에 있든 같은 코드로 옮겨짐 |
| 회차 생성 권한(참여자·소유자·관리자)과 열린 회차 하나 제한은 `Store.studies.create`에서 검사. 이전 회차 재개에도 같은 제한 적용 | 브라우저와 MCP가 같은 규칙을 지켜야 하며, 열린 회차가 둘이면 다음 발표자·회차 안내가 달라짐 |
| 격주 일정은 요일을 먼저 맞춘 뒤 지난 주기를 건너뜀. 요일은 0–6 정수만 저장하고 서버 스냅샷 캐시는 날짜가 바뀌면 갱신 | 요일 변경 후 이번 주 회차를 건너뛰거나, 자정 이후에도 어제 계산한 다음 회차가 보이는 문제 방지 |

## 2026-10-22 — 분야·방법론 정리

| 결정 | 이유 |
|---|---|
| 분야 = 교통 문제, 방법론 = 기법. 지도 영역(자동 묶음)은 태그가 아님 | 지도 영역 이름이 분야처럼 붙어 있어 "분야에 AI가 있다", "신호와 CAV가 묶였다"로 읽힘. 영역 이름 정리는 다음에 |
| 분야: "교통류·상태추정" → **교통류 이론**, 상태추정은 "교통 예측"과 합쳐 **교통 상태추정·예측**. "전기차·에너지" → **전기차·충전·에너지** (id는 그대로) | 한 분야에 교통류 이론·상태추정·예측이 섞여 있었음 |
| 방법론: "생성모델·월드모델" → **생성모델** / **월드모델**, "LLM·VLM·에이전트" → **LLM·VLM** / **에이전트**, **프로그램 합성·기호 회귀** 추가. 새 태그는 색이 밀리지 않게 목록 끝에 | 서로 다른 연구 흐름이 한 태그에 묶였고, 프로그램 합성 계열은 칸이 없어 "최적화·OR"로 들어갔음("programming" 규칙이 genetic programming까지 잡던 것도 고침) |
| 다이어리는 분야나 방법론 태그가 하나 이상 있어야 게시(AI 초안도 같음). 맞는 게 없으면 **누구나** 새 분야·방법론을 만들 수 있음(이름이 같으면 기존 태그 재사용). 병합·이름 바꾸기는 관리자 | 태그 없이 게시된 다이어리는 지도·분야 페이지·사람 페이지 어디에도 잡히지 않았음. 관리자만 만들 수 있으면 가장 가까운 기존 태그로 잘못 들어감. 늘어난 태그는 매달 정리 알림에서 관리자가 합침 |
| 서로 다른 태그 이름의 정규화된 id가 겹치면 새 id를 발급. 병합으로 사라진 id도 다시 쓰지 않으며 생성 id에도 다이어리와 같은 40자 정규화 적용 | `A/B`와 `A B`가 같은 태그로 저장되거나, 병합한 이름을 다시 만들 때 태그가 보이지 않는 문제 방지. 기호뿐인 이름도 다이어리에 저장할 때 id가 달라지지 않음 |
| 연구 지형 로즈의 축: **지도 지역(8) → 분야 전부(17)**, 방법론은 **상위 7 + 기타 → 전부(18)**. "기타" 꽃잎 없음. 분야가 없는 일반 AI 논문 비중은 분야 로즈 아래 한 줄로 알림 | 지도 지역은 자동 묶음이라 사람의 관심을 읽기 어려웠음. 상위 8 + 기타면 사람에 따라 기타가 최대 57%라 소수 분야 연구자가 안 보였음. 17장도 220px에서 읽히고, 모두 같은 축이라 비교·평균 점선이 그대로 됨 |
| 사람 서랍·페이지의 "세부 분야" 막대를 없앰 | 분야 로즈 범례와 같은 내용이 두 번 나옴 |
| **지도 영역을 없앰.** 지도는 분야 지도·방법론 지도 두 장: 글 임베딩(SPECTER2, 평균을 뺌) 뒤에 분야(또는 방법론) 태그 벡터 × 0.4를 붙여 UMAP. 방법론 지도는 분야 지도에서 출발해 같은 방향으로 맞춤 | 사람이 같은 태그로 묶은 논문이 모이게. 실험(논문 2,309편): 이웃 10편 중 같은 분야 65% → 83%, 글 내용상 이웃 유지 30% → 28%. 가중 1.0은 태그별 섬으로 쪼개져 버림 |
| 그래프에 **분야 / 방법론** 전환. 위에서 아래로 도는 애니메이션(세로를 cos로 접었다 펼침), 움직임 줄이기 설정이면 바로 바뀜 | 두 지도를 같은 점이 오가는 한 장면으로 보여 줌. sigma.js는 2D라 진짜 3D 대신 전환으로 |
| 배경 영역 = **태그마다 밀도 등고선 덩어리**(그 태그 논문의 약 70%를 감싸는 높이, 작은 조각은 버림) + 가운데 태그 이름. 지도 영역 이름 짓기·관리자 도구·`clusterNames` 기록은 지움 | 영역 이름이 분야처럼 읽혀 혼동됐음. 태그 이름을 그 태그 논문이 모인 자리에 두면 따로 이름 지을 일이 없음. 밀도 등고선이라 멀리 튄 논문은 빠지고 경계가 부드러움 |
| 학기 필터를 적용해도 새 논문의 두 지도 좌표(`x/y`, `mx/my`)는 전체 논문에서 계산한 값을 유지 | 방법론 지도만 필터마다 새 위치로 바뀌지 않도록 함 |

## 2026-10-03 — 사람 페이지와 내 페이지의 역할

| 결정 | 이유 |
|---|---|
| **사람 페이지 = 프로필**(모두에게 같은 화면, 전체 기간), **내 페이지 = 이번 학기 작업 공간**(나만, 학기 단위), **서랍 = 훑어보기** | 두 페이지가 "무엇을 읽어왔나"(연구 지형 / 관심사 변화)와 다이어리 목록을 각자 다른 모양으로 보여 줘서 역할이 겹쳤음. 할당량·달력·docx 내보내기는 원래 학기 단위라 기간으로 나누면 자연스럽게 갈림 |
| 관심 변화 차트를 내 페이지에서 사람 페이지로 옮김. 줄 = 학기(전체), 학기를 고르면 그 학기의 달 | 관심의 변화는 그 사람의 초상이지 할 일이 아님. "월별/학기별" 전환 대신 다이어리 목록의 학기 필터를 따라감 |
| 사람 페이지의 사이드에 서랍 렌더 함수를 쓰지 않음 — **patterns §2-B 예외** | 340px 칸에 서랍 내용을 그대로 넣으니 범례가 잘리고 숫자 라벨이 두 줄이 됨. 큰 화면에서는 연구 지형을 양쪽(지도 지역 · 방법론)으로 넓게 그림 |
| 다이어리 목록은 한 컴포넌트(`diaries.js`): 월별 접기 + 한 줄 행, 누르면 그 자리에서 펼쳐 읽음 | 사람 페이지(다이어리 전문 카드 나열)와 내 페이지(한 줄 목록)가 달랐음 |
| 편집·삭제는 내 페이지에서만. 사람 페이지는 내 것이어도 읽기 전용 | 프로필은 남이 보는 모습 그대로. 다이어리에서도 편집으로 갈 수 있음 |
| 사람 페이지 목록에는 별점·별점순 정렬을 두지 않음 | 사람 페이지는 정보만 (별점을 신호로 쓰지 않음). 내 페이지에서 내 것끼리는 정렬 가능 |

## 2026-10-04 — 폰 화면과 속도

| 결정 | 이유 |
|---|---|

| 아이콘은 **Lucide 유지** | Apple SF Symbols는 라이선스상 웹에 쓸 수 없음. iOS 스타일의 Ionicons(선택된 탭은 채운 아이콘)와 얇게 다듬은 Lucide를 폰 바에서 비교했으나 지금 그대로 둠 |

## 2026-10-03 — 컴포넌트로 옮기기 (정리 5단계)

| 결정 | 이유 |
|---|---|
