# 결정 기록

규칙을 바꿀 때는 이 문서에 날짜·결정·이유를 먼저 적고, 해당 규칙 문서를 고친다.
HIG와 다르게 정한 것은 **HIG와 다름**으로 표시한다.

## 2026-10-03 — 컴포넌트로 옮기기 (정리 5단계)

| 결정 | 이유 |
|---|---|
| `tokens.css`를 맨 먼저 불러오고, 컴포넌트 선택자를 `:where([data-ui]) .ui-x`로 (우선순위 = 클래스 하나) | 컴포넌트가 페이지 규칙보다 늦게·높은 우선순위로 와서, 페이지에서 배치를 바꾸려면 `!important`나 긴 선택자가 필요했음 (폰 언어 전환·모달 폭이 이 때문에 깨졌었음) |
| `ui-btn` 기본 모양 = 회색 바탕 + 검정 글자 (강조색 글자 아님), `.neutral` 없앰 | macOS 푸시 버튼. 강조색 글자 버튼은 iOS 방식 |
| 문장 안 글자형 버튼 `.ui-btn.text` 추가 | `.link-btn` 47곳의 역할 — `.plain`은 높이·여백이 있어 문장 흐름을 깸 |
| 선택 상태는 `.on` 클래스 대신 `aria-pressed` / `aria-current` | 화면 읽기 프로그램이 켜짐·현재 위치를 알 수 있음 |
| 동작하는 칩(날짜 이동, + 태그 추가)은 `ui-btn small`, 투표는 `ui-btn small` + `aria-pressed` | components §1·§6: 칩은 켜고 끄는 필터만 |
| 모든 기본 입력창이 우선순위 0 규칙으로 같은 모양 | 입력창 15곳에 클래스를 붙이는 대신, 문맥 규칙에서 모양을 지우고 폭만 남김 |
| 시트(LabModal) 버튼은 아래 오른쪽 그대로 | macOS 시트의 배치. 문서의 "머리에 취소·완료"는 iOS 방식이라 폰 전용으로 고침 |
| 행 16종에 `ui-row` (+ `.two` `.rich` `.ruled`), 옛 클래스는 칸 배치만 | 높이·여백·호버·구분선·글자를 한곳에서. 데스크톱 행 28px |
| 상단 바 안 컨트롤(학기·알림·검색·내 메뉴)은 상단 바 컴포넌트로 둠 | 한 곳에서만 쓰는 툴바 요소라 범용 버튼으로 옮겨도 얻는 것이 없음 |
| 논문 목록 카드(`.paper-row`)·질문 카드(`.st-q`)는 카드 그대로 | 목록 묶음으로 바꾸면 화면이 크게 달라져서 따로 정함 (열린 문제) |
| 리팩터링 확인은 화면 34장의 픽셀 비교로 | 의도하지 않은 변화(예: CSS 순서 변경 → 0.01%)를 숫자로 확인 |

## 2026-10-03 — 차트 색 (정리 4단계)

| 결정 | 이유 |
|---|---|
| 분야·방법론·지도 영역·학회·연도 색은 시스템 색 이름으로 저장하고 `rgb(var(--이름))`으로 그린다 | 다크·고대비를 따라가게. 팔레트 네 계열이 섞여 있었음 |
| 옛 팔레트 hex는 불러올 때 이름으로 변환 (`store.js`의 `dataColor`), `build_site.py`는 이제 이름을 쓴다 | 이미 만들어진 `data.js`·데모 데이터를 다시 빌드하지 않아도 됨 |
| 태그 색은 축 안의 순서대로 12색 | 옛 방법론 팔레트가 11색이라 14개 태그에서 같은 hex가 겹쳤음 |
| 관리자 태그 색: 아무 색 고르기 → 시스템 색 목록 (옛 hex 태그는 그대로 선택 가능) | 태그 색도 테마를 따르게 |
| 사람 색 기본 배정: 회색 제외, 갈색 두 명 → 분홍·갈색, 회색 → 남색 | 회색은 "기타·없음"의 뜻. 실제 연구실에서 옛 기본색을 쓰던 두 명의 색이 바뀜 (직접 고른 색은 그대로) |
| 그래프가 테마 바뀜을 받아 다시 칠함 — 테마를 바꿀 때 새로 고침하지 않음 | 예전에는 WebGL 색을 불러올 때 한 번만 계산해서 새로 고침이 필요했음 |
| 쓰기 달력의 진하기: 요소 투명도 → `color-mix()` | 고대비·다크에서 바탕과 섞이지 않게 |
| hex가 꼭 필요한 데이터 표(사람 색 팔레트, 옛 팔레트 변환표)는 `// design-lint: off … on` 구간으로 검사에서 뺌 | 정당한 예외를 기준선에 숫자로 묻어 두지 않고 위치를 드러냄. 이 구간은 `store.js` 한 곳뿐 |

## 2026-10-03 — 기존 코드 정리 (1차)

| 결정 | 이유 |
|---|---|
| 글자 토큰을 macOS 값으로 바꾸고, 폰(≤760)은 iOS 값으로 자동 전환 | 규칙집의 기준 플랫폼을 코드에 반영 |
| 크기만 바꾸는 `--fs-*` 토큰 추가 (`--t-*`는 `--fs-*/--lh-*`로 조합) | 옛 CSS의 `font-size`만 쓴 규칙 159곳을 `font` 축약형으로 바꾸면 굵기·줄높이가 초기화됨 |
| 옛 px 크기는 macOS 단계로 옮김: 34·28 → 26·22, 22·20 → 17, 18·17·16 → 15, 15·14·13 → 13, 12 → 12, 11 → 11, 10 이하 → 10 | 한 단계씩 작아지는 macOS 밀도 |
| 따로 지정된 긴 글의 줄높이(1.5–1.7)는 그대로 둠 | 열린 문제 "긴 한글 문단의 줄높이"를 실제 화면으로 비교하기 전까지 지금 가독성 유지 |
| 둥글기 `--r-xs`(4) 추가 → 6단계 | 체크박스·키 표시처럼 작은 사각형에 8은 너무 둥긂 |
| 의미 토큰 추가: `--warn`, `--on-color(-2/-fill)`, `--scrim(-light/-strong)`, `--shadow-seg`, `--shadow-knob`, `--text-shadow-on-color`, `--av-*` | 직접 쓴 색 74곳이 이 몇 가지 역할의 반복이었음 |
| 아바타 4크기(20·28·36·56)로 통일, 이니셜은 폰에서도 고정 | 18가지 크기가 있었고, 폰에서 이니셜이 커져 두 줄로 깨졌음 |
| 화면 폭 기준점 예외: ≤ 420px (상단 바 탭 맞추기만) | 360px 폰에서 탭 6개가 한 줄에 들어가야 함 |
| 사람 페이지 연구실 카드의 1100px 기준점 → 컨테이너 쿼리 | 화면 폭이 아니라 그 칸의 폭에 따라 바뀌는 배치 |
| `!important` 예외 2곳: `[hidden] { display: none !important }`, 폰의 `.pop { left: 12px !important }` | 앞은 브라우저 기본 동작을 바로잡는 표준 방식, 뒤는 JS가 넣은 인라인 위치를 덮어써야 함. 나머지 12곳은 선택자 우선순위를 바로잡아 없앰 (전역 입력창 규칙을 `:where()`로) |
| 화면 문구의 "리뷰" → "다이어리", "{이름}님" → "{이름} 님" | writing.md 용어집 |
| 읽을 목록의 `prompt()`·`confirm()` → 시트·`LabConfirm` | components §15–16 |

## 2026-10-03 — 규칙집으로 개편

| 결정 | 이유 |
|---|---|
| `docs/DESIGN.md`(리뉴얼 계획서)를 `docs/design/` 규칙집 7개 문서로 나눔. 옛 문서는 [archive/2026-10-renewal.md](archive/2026-10-renewal.md)로 보관 | 계획서로는 새 기능을 만들 때 무엇을 쓸지 알 수 없었음. 실제 CSS에 글자 크기 19종, 둥글기 18종, `ui-*` 컴포넌트 실사용 4곳으로 문서와 코드가 어긋나 있었음 |

| 데스크톱 글자는 **macOS 원값 그대로** — 본문 13, 최소 10, 다이어리 본문도 13 | 네이티브 앱과 같은 밀도. 한글 보정(최소 11, 읽는 글 15)안은 고르지 않음. 지금 화면이 실제로 많이 쓰는 크기(13 / 12)와도 가까워 고칠 양이 적음 |
| 데스크톱 컨트롤 기본 높이 28 (작은 22, 큰 34) | HIG macOS 기본 컨트롤 크기 28×28, 최소 20×20 |
| 레이아웃은 **상단 바 유지** (사이드바 구조로 바꾸지 않음) | macOS 앱의 사이드바도 검토했으나, 2026-10-02 결정을 다시 확인 |
| 화면 용어 **다이어리**로 통일 ("리뷰" 쓰지 않음) | "Paper Diary"라는 서비스 정체성. 지금 리뷰/다이어리가 같은 대상을 가리키며 섞여 있었음 |
| 버튼 문구는 **Apple 한국어 방식** (저장·삭제·편집·추가·완료·취소, 대상이 필요하면 "다이어리 쓰기") | iOS·macOS 한국어 UI와 같은 말. "~하기"보다 짧음 |

| 사람 색은 **자유 선택 유지** — 테마를 따르지 않는 유일한 예외 | 멤버가 자기 색을 고르는 재미를 지킴. 대신 표시용으로만 쓰고 글자색은 자동 |
| 사람 외의 데이터 색(분야·지도 영역·학회·연도)은 시스템 색 이름으로 | 팔레트 네 계열(Material·Apple·GitHub·Tokyo Night)이 섞여 있었고, 다크·고대비를 따라가지 않았음 |
| 둥글기 5단계: 20 · 14 · 10 · 8 · 완전 | 동심원 규칙(메뉴 14 − 여백 6 = 항목 8). 그전 문서는 4단계였으나 작은 컨트롤·메뉴 항목에 8이 필요 |
| 화면 폭 기준점 2개: 760(폰) · 900(1단) | 지금 720 · 600 · 420 · 360이 흩어져 있었음 |
| 2단 레이아웃의 사이드 폭 340 | 지금 320 / 340 / 360이 섞여 있었음 |

## 2026-10-02 — Apple HIG 리뉴얼

| 결정 | 이유 |
|---|---|
| 테마: **자동(기기 설정) + 앱에서 바꾸기**(자동·라이트·다크), 기본값 자동 — **HIG와 다름** | HIG는 앱 전용 외관 설정을 두지 말라고 하지만, 연구실 공용 PC를 고려해 허용 |
| 강조색 **Indigo** | 기존 보라(#a882ff)와 가장 가까운 시스템 색 |
| 다크 바탕은 순수 검정 대신 gray6 → gray5 → gray4 — **HIG(iOS)와 다름** | 데스크톱 웹에서 순수 검정은 대비가 너무 강함 |
| 데스크톱은 위에 붙은 얇은 반투명 상단 바(apple.com식). 사이드바(Apple Music 웹식)는 `layout.css`에 레거시로 보관 | 화면을 넓게 쓰고, 기존 구조를 크게 바꾸지 않음 |
| 폰은 두 줄 떠 있는 바 유지 | 하단 탭 바로 바꾸는 것보다 변경이 적음 |
| 견본 페이지(`#/design`)를 먼저 만들고 확정 후 적용 | 실제 화면을 건드리기 전에 라이트/다크/고대비를 나란히 검토 |
| 상단 바의 큰 검색창 → 돋보기 + 스포트라이트식 전역 검색 (`/`, ⌘K) | 검색창이 사실상 논문 목록 필터였음. 전역 검색과 목록 필터를 분리 |
| 홈 피드 탭: 글 위에 뜬 유리 캡슐 → 상단 바 아래 고정되는 불투명 줄 + 스크롤 가장자리 효과 | HIG: 유리는 내비게이션 층에만, 콘텐츠와는 scroll edge effect로 분리 |
| 보조 글자 `#6e6e73`(라이트), 링크 `#0066cc` / `#2997ff` | iOS 측정값이 4.5:1 대비를 못 넘어서 apple.com 값으로 조정 |
| 글꼴: 시스템 글꼴 + Pretendard, 아이콘: Lucide | SF 폰트 파일·SF Symbols는 웹에서 쓸 수 없음 (라이선스) |
| 확인창: 브라우저 `confirm()` → HIG 알림 (`LabConfirm`) | |

## 열린 문제

| 문제 | 상황 | 다시 볼 때 |
|---|---|---|
| **긴 한글 문단의 줄높이** | macOS 표의 13/16(1.23)은 한 줄 UI 글자 기준이라, 여러 줄 다이어리 본문에서는 빽빽할 수 있음. 지금 화면은 1.6을 씀 | 글자 토큰을 macOS 값으로 바꾼 뒤 실제 다이어리로 비교 |
| **윈도 저해상도 화면의 10–13px 한글** | 연구실 윈도 PC(일반 모니터)에서 Pretendard 10–11px의 선명도 | 토큰을 바꾼 뒤 실제 PC에서 확인. 필요하면 "윈도에서만 최소 11" 같은 보정 검토 |
| 의미 색 값 **[외부]** | Apple이 값을 공개하지 않아 iOS 측정값 사용 | macOS 26 / iOS 27 Figma 키트로 다시 맞춤 |
| 레거시 사이드바(`data-layout="sidebar"`)를 계속 둘지 | 상단 바 유지가 확정되면 지워도 됨 | CSS 정리 단계 |
| 사람 색 자유 선택의 고대비 대응 | 사람 색은 고대비에서 바뀌지 않음 | 접근성 점검 때 |
| 논문 목록을 카드 대신 목록 묶음(`.ui-list` + `.ui-row.rich`)으로 | 지금은 논문마다 카드. macOS 앱이라면 표·목록에 가까움 | 화면 비교 후 결정 |
| `apple.css` 없애기 | 페이지별 덮어쓰기가 남아 있음 (컴포넌트로 옮긴 부분은 지움) | 페이지별로 style/features에 합치기 |
